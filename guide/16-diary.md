# 16 日记

[← 返回目录](README.md) | 上一章：[15 导入、批量操作与导出](15-import-export.md) | 下一章：[17 AI 写作 →](17-ai-writing.md)

日记是一个**独立的写作空间**：打开就是今天，写完自动归档到年月。桌面按 `⌘3` 进入，Android 在首页底部 Dock（底部五格）点第 3 格「日记」。

> **日记本是固定的**：像回收站一样，不能取消、不能删除；想把某篇留下来当普通文档，用「转为文档」（见下）。
>
> 一个关键事实：**日记不是新的文档类型**。它就是放在「日记」笔记本里的普通 Lake 文档，标题就是日期（形如 `2026-11-09`）。所以历史快照、回收站、全文搜索、导出、云同步全都直接可用，不需要额外设置。
>
> **v1.1.1 起的行为变化**：日记本改为固定容器 —— 不可取消、不可删除、不可改名 / 换图标 / 排序；同时新增「转为小记」出口（复制原正文与图片 / 附件，原稿移入回收站，可恢复）。

## 打开日记

| 平台 | 入口 |
| --- | --- |
| 桌面 | 左上空间菜单 →「日记」（`⌘3`） |
| Android | 首页底部 Dock 第 3 格「日记」 |

- 桌面左栏是「年 → 月 → 日期」的时间线，可以拖动加宽（宽度只记在本机）
- 日记本在知识库树里不显示，也**没有改名 / 换图标 / 排序入口**（固定标识，见下）
- 页面顶部从左到右固定三个按钮：**搜索、日历、＋**

## 写今天

| 动作 | 含义 |
| --- | --- |
| 写今天（主按钮） | **幂等**：今天已经写过就打开最近那一篇，不会重复建 |
| ＋ | **永远新建一篇**（所以今天可以写多篇，行内用时刻区分） |
| 日历 | 选任意一个日期去新建（应用内月历，不是系统日期选择器） |

- Android 同样三件事：今日卡主按钮「写今天 / 继续写今天」= 幂等，`＋` = 今天新建，日历 = 按日期新建
- 同一天多篇时，时间线按**创建时间**倒序（不是修改时间 —— 改旧的那篇不会把它顶到前面）

## 年 / 月分组

- 结构是 `日记 → 2026 → 11 → 2026-11-09`；「2026」「11」两级分组在第一次写入时**自动创建**
- 这些分组就是普通目录节点，会随云同步传播到其它设备
- 日记子树顺序是**固定的编年顺序**（年 → 月 → 日期）：不能拖拽、也不提供排序 / 重排；其它笔记本照旧可拖

## 搜索

- 日记就是文档，正文已经在全文索引里：桌面 `⌘K`、Android 顶部搜索都能搜到
- 日记空间自己有「搜索」入口，可以把范围先收窄到日记
- 标题只能是日期，**改名会被直接拒绝**（否则时间线会乱）

## 转为文档 / 转为小记

日记条目有**两种留下它的方式**（桌面条目**右键**、Android 条目 **⋯** 都能用，同名同语义）：

### 转为文档（移动）

「转为文档…」→ 在弹窗里选一个**知识库（笔记本）**、可改标题 → 确认。

- 弹窗与 AI 写作的「生成文档」是同一个：**只到笔记本这一层**（不选分组、不会出现日记本），标题默认是日期、可以改
- 这是**移动**，不是复制：正文、历史快照、标签关系、云端索引全部跟着这条日记走，不复制、也不改格式、不删；先移动、再改名（日记条目的标题不接受原地改写），任何一步失败都会提示，不会假装成功
- 移出后它自然从日记时间线消失；**日记本不是移动目标，普通文档无法移入日记本**（想继续写日记，回日记空间用「写今天 / ＋」）

### 转为小记（原样复制正文 + 搬运图片/附件，原文进回收站）

「转为小记」→ 用这篇日记**原样**创建一条小记：正文照搬，**图片/附件一起搬过去**（复制到小记的资产目录，日记原稿的资产保留）；随后**日记原文移入回收站**（软删、**可恢复**，不是彻底删除）。

- **Android 入口**：日记页条目 ⋯ →「转为小记」→ 先确认「图片/附件会一起复制到小记；原日记会移入回收站（可恢复）」→ 完成后弹提示（搬不了的卡片类型会逐项写明），处理中不会重复触发
- 小记是**另一条数据**；日记原文仍在回收站，想反悔可以从回收站恢复（原稿与它的图片/附件都还在）
- 小记承载不了的卡片（画板、大纲、素材库、未知卡片等）会被剥掉，但**提示里会逐项写明未搬运**，绝不静默丢内容
- **表格 / 多维表 / 画板 / 手写板类型的日记不能转小记**：它们的正文不是 Lake 文本，界面会提示先「转为文档」再处理

> **跨空间只允许这两个单篇出口**（261112 用户裁决）：没有「取消整本日记标记」入口——日记本就是日记本；两种做法都**不支持反向移入**（日记本不作为移动目标、也不出现在知识库树里）。

## 删除与恢复

- 删除 = 移入回收站（软删，可恢复），走和文档完全相同的确认与路径
- 恢复 = **原路返回**：原年/月分组还在就回原位；分组已被删掉会按标题日期把年 → 月补回来
- 回收站里日记条目带「日记」徽标；彻底删除后不可恢复
- 详见 [09 历史快照与回收站](09-history-trash.md)

## 没有做什么

- **不做标签**：日记不提供打标签入口，也不进标签空间的聚合
- 不做缺天提醒、打卡连续天数、提醒
- **日记本不可取消、不可删除、不可改名/换图标/排序**（261112 用户裁决）：没有「取消日记标记（整本）」入口，也不提供删除日记本；内容顺序固定编年（年 → 月 → 日期），不能排序/重排。想留下某篇用**两个单篇出口**——「转为文档」移动到知识库，或「转为小记」生成小记并把原文移入回收站（可恢复）；日记本不作为移动目标，也不出现在知识库树里
- 为什么这么严：日记空间靠「固定容器 + 固定顺序」成立；一旦能取消或能排序，它就退化成普通笔记本（与知识库没有区别）
- 不提供月历**浏览**：日历只用于「选一个日期去写」，不是翻看或管理月历
- 没有心情、天气、位置这类字段

## 和「默认空间」的关系

设置 → 常规 → 启动 →「默认空间」可以让应用启动时直接落在日记（只记在本机，不参与同步）。桌面五个一级空间都可选，Android 是首页五格都可选，默认分别是知识库与小记，见 [12 设置项逐条](12-settings.md)。

## 两个平台的小差别

| 项 | 桌面 | Android |
| --- | --- | --- |
| 按日期新建 | 有（应用内月历） | 有（同一套月历，包在底部弹层里） |
| 一天多篇 | 支持 | 支持 |
| 转为小记 | 条目右键菜单 | 条目 ⋯ 菜单（同语义） |
| 左栏宽度 | 可拖（本机记忆） | 无左栏 |
| 日记标签页 | 与文档标签页分开计数，退出重开不恢复 | 单文档工作区；从日记进入后返回回日记页签 |

> 正文可以随便写：标题就是日期，不用自己整理层级。想把它变成一篇正式文档时再走「转为文档」；想留一个「以后再说」的版本，用「历史版本」手动打快照（见 [09](09-history-trash.md)）。
