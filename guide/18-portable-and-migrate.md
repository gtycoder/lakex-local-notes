# 18 换机、便携包与迁移

[← 返回目录](README.md) | 上一章：[17 AI 写作](17-ai-writing.md) | 下一章：[19 更新中心 →](19-update-center.md)

换设备时，数据有两条路可走：**便携包**（离线全量搬一次）和**S3 同步**（增量拉取）。另外还有一个只搬「配置」的小工具：**迁移码**。选错路会白折腾，这一章把三条路的边界说清楚。

## 三条路怎么选

| 方式 | 搬什么 | 适用 | 代价 |
| --- | --- | --- | --- |
| 便携包 | 桌面全部笔记、资源、小记、标签、回收站（**不含历史快照**） | 桌面 → Android 首次落地，想省 S3 首轮全量流量 | 一次性，不做增量；包是明文 |
| S3 同步 | 两端的全部笔记与资源（按变化增量） | 已经有一个私有桶，且两端都能联网 | 首轮全量要传/拉一遍，流量与时间取决于库大小 |
| 迁移码 | **只有 S3 配置**，不含任何笔记 | 已经在用 S3，只想把配置搬到另一台设备 | 不解决数据搬运，只省手工填表 |

> 三者可以叠加：先用便携包把手机灌满，再配好 S3 只做增量 —— 这是最省流量的一条组合路径。

## 便携包：桌面 → 手机

### 导出（桌面）

设置 → 备份与恢复 →「迁移到手机」→「导出便携包（桌面 → 手机）」。

- 产物是**一个文件**：`lakex-portable-YYYYMMDD-HHmmss.zip.lln`（后缀固定，不要改名成普通 `.zip`）
- 上限 **4GiB**，超出会直接失败并提示，**不分卷**
- 包含：正文、资源、小记、标签、回收站
- **不包含**：历史快照、日志、草稿、S3 密钥、本机的窗口/界面状态、同步意图账本
- 未配置 S3 也能导出（纯离线包）；**已开启云同步时，导出前会自动同步一次**，成功才继续；同步失败则导出失败，不会产出不完整的包
- 包里是**明文笔记**，不加密：走网盘或聊天工具中转请自行判断风险

### 导入（Android）

设置 → 备份与恢复 →「从便携包导入（覆盖本机）」→ 选文件 → **二次确认** → 等待进度 → 完成提示计数。

- 导入是**覆盖**，不是合并：当前手机上的笔记、小记、标签、回收站会被替换。建议先导出当前数据备份，或确认手机上是空库
- 导入前会先把现有数据隔离保存一份（不删除），失败或中途断电，下次启动会按记录自动回滚到导入前
- 导入完成后**不强制**配置 S3：可以先离线用；以后配好同一个桶，只需增量同步
- 手机导入后会补一个固定的「回收站」目录，所以目录数可能比清单多 1，属正常

### 便携包不做的事

- 不做增量包、不做分卷、不做加密
- 手机 → 桌面不支持（请在桌面用「从云端恢复」或整库备份）
- 不搬 AI 会话（会话只在本机，见 [17](17-ai-writing.md)）

## S3 同步：增量那条路

已经在用 S3 时，换机不需要便携包：

1. 老设备上完成一次同步（确认「已同步」）
2. 新设备上用**配置迁移**把 S3 配置导入（见下），或手工填 Endpoint / Access Key / Secret Key / Bucket / Region
3. 打开「启用云同步」，让它先拉后推
4. 如果新设备本地库坏了，用设置 → 备份与恢复 →「从云端恢复」：当前数据先改名隔离，再从云端全量拉取重建，**不会**把本机数据传上去覆盖云端

详见 [11 云同步](11-cloud-sync.md)。

## 迁移码：只搬配置

- 桌面：设置 → 云端与同步 →「配置迁移」→「导出到文件…」得到一个只含 S3 配置的 `.json`（密钥已加密）
- 手机：设置 → 云端与同步 →「配置迁移」→「从文件导入」（或粘贴 `LLN1.` 开头的迁移码）
- **它只防误读，不是安全边界**：内层加密用的是固定种子，任何拿到这个文件的人都能解开 —— 别外传、别贴到聊天工具
- 桌面导出/导入在**主进程**里完成，界面层从不接触明文 Secret

## 整库备份：留一份能自己打开的全量

设置 → 备份与恢复 →「整库备份（完整目录）」：把数据库快照、正文、资源、**历史快照**、小记完整复制到你选的空目录。

- 与便携包的区别：整库备份**含历史快照**，用来看得懂、找得回的文件形态归档；便携包是为了给手机落地
- 自动备份（仅数据库）：每天或每周把主库与小记库打快照到本机目录，保留最近 N 份并限制总大小，**不含**正文与历史
- 从数据库快照恢复：校验通过后，当前库改名隔离（可找回）再替换，重启生效

## 换机检查清单

1. 老设备：完成一次同步（或先做一次整库备份）
2. 想省流量 → 导出便携包；只想增量 → 直接配 S3
3. 新设备：导入便携包 / 配置 S3 并打开云同步
4. 对照抽查：笔记本数量、最近编辑的几篇、小记时间线、几张大图能否打开
5. 确认无误后，再考虑在老设备上清理数据（清理前务必确认云端与备份都在）
