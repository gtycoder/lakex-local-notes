## 0. 结论摘要（先看这 6 条）

1. **钉钉移动端多维表 = 文档页 + 顶部视图页签**：`表单 | 内容` 两个页签 + 右上「视图列表」；内容视图再分「记录展示方式 = 表格 / 卡片」两套布局。**卡片不是独立视图类型，是表格视图的布局变体**（新建视图里只有 甘特/表格/看板/画册/日历/表单 六种）。
2. **表单有两个态**：有编辑权限时点「表单」直接进**编辑表单**（编辑题目/封面/样式，底部是 排序·样式·设置·完成）；填写者看到的是**填写表单**（字段卡片 + 底部「提交」）。用户要求我们默认进**填写**。
3. **视图配置 = 一个底部面板的三个页签**：筛选 / 排序 / 布局；布局页签就是用户给的那张图（记录展示方式、封面设置、卡片布局方式 1/2/3 列、标题 主/副、展示字段/未展示字段），**改完立即生效**。
4. **记录详情是全屏页**（不是底部面板）：标题 = 主字段值，字段逐行 label/value，底部 1/N 翻页 + 写评论。我们只读态去掉编辑/评论，只留翻页。
5. **我们已有的底子比预期好**：core/bitableDoc.ts 早就定义了 grid|form|kanban|gallery|calendar 五种视图与 BitableView 全套配置（含 form 字段配置），桌面 5 种视图都已实现；**移动端只渲染了表格**，且没有视图切换/筛选排序/表单入口（§7）。
6. **关键冲突点（要用户拍板）**：布局配置在钉钉属于**文档数据的视图配置**；我们的文档默认只读 ⇒ 真机上「切布局」= 写正文。建议按「本机视图」落设备本地（同 activeViewId 口径），只读态可切、不产生同步；否则只能进编辑态才能切（§10-Q2）。

## 2. 钉钉的信息架构（移动端）

```text
文档页（顶部：← 标题/表名  ⋮  ×）
├─ 视图页签：表单 | 内容                    右上 ≡（视图列表）
├─ 内容视图
│   ├─ 工具行：N 条记录 >        ⚙ 设置 | 筛选 | 视图配置
│   ├─ 表头：字段（首列固定序号，列头可点 = 字段菜单）
│   ├─ 分组行：按「日期」分组，右侧「N 条记录 ▾」可折叠
│   ├─ 数据行（整行可点 → 记录详情；条件填色整行底色）
│   └─ 底部：每分组一个「+」；右下浮动 表情/＋
├─ 表单视图
│   ├─ 编辑态（有权限）：封面 + 标题 + 题目卡（01 老师 / 02 附件 / 03 日期）+ 底部 排序·样式·设置·完成 + 插入题目
│   └─ 填写态（填写者）：封面 + 白色卡片（标题/说明）+ 字段卡片 + 底部「提交」+ 右下铅笔（有权限才回编辑态）
└─ 底部面板：视图配置（筛选/排序/布局）、视图列表、字段菜单、统计、表操作
```

## 3. 内容视图 = 表格视图 + 两套记录展示方式

### 3.1 表格布局（默认）
- 分组：按**日期字段升序**分组，组头 `▾ 06月09日`，右侧 `1 条记录 ▾`（可折叠）。
- 列：**序号列固定在最左**；可见 2 列（如 老师 / 信息提取），其余列横向滚动。
- 行高约 46px（CSS），单元格上下 6 / 左右 8；行间 0.5px 分隔；整行可点进详情。
- **条件填色**：命中规则的整行铺底色（截图里 06月10日/06月16日/06月17日 的「财智-早」行为浅黄底）。
- 每分组末尾一行「+」（增行）；右下浮动「表情 + ＋」。
- 列头点击 = **字段菜单**：编辑字段 / 复制字段 / 按 A→Z·Z→A 排序 / 按本字段筛选 / 向右插入列 / 修改统计方式 / 删除字段。
- 工具行 `18 条记录 >` 右侧三枚图标：⚙ 统计 · 筛选 · 视图配置（后两者打开同一个底部面板）。

### 3.2 卡片布局（同一视图的另一套展示）
- 分组照旧；卡片单列（也可 2/3 列）。
- 卡片结构 = 主标题（本视图选了「老师」，渲染为**彩色单选 chip**）→ 展示字段逐行 `字段名 + 值`（信息提取 / 附件 / 日期）→ 可选封面图。
- 卡片之间约 10px，卡片圆角约 12px，白底、无边框、靠底色差分层。
- 2 列时字段改成「标签在上、值在下」。钉钉还有 3 列，但在 412 宽手机上只能放主字段、信息全被截断 ⇒ **用户 261030 决定只做 1 / 2 列，不做 3 列**。

### 3.3 视图配置 → 布局（用户给的那张图，逐项对齐）

| 区块 | 控件 | 说明 |
| --- | --- | --- |
| 记录展示方式 | 卡片 / 表格（两个示意磁贴） | 切换 = 同一视图的布局，立即生效 |
| 封面设置 | 「显示封面」Switch + 副文案「将附件字段中的图片显示为封面」 | 仅卡片布局出现 |
| 卡片布局方式 | 1 列 / 2 列（钉钉另有 3 列；用户 261030 定：不做 3 列） | 仅卡片布局出现 |
| 标题 | 主标题（当前 = 老师）· 副标题（当前 = 不显示副标题），右侧 > 选择字段 | 仅卡片布局出现 |
| 展示字段 | 字段行（⊖ 移除 + 拖拽手柄） | 仅卡片布局出现 |
| 未展示字段 | 字段行（＋ 加回 + 拖拽手柄） | 仅卡片布局出现 |

> 细节：面板顶部是三页签（筛选 / 排序 / 布局），**同一面板切页签不换 sheet**；布局改动即刻写回视图配置并重绘列表，没有「保存」按钮。

## 4. 表单视图：编辑态 vs 填写态

| | 编辑态（有权限点「表单」默认进入） | 填写态（填写者/预览） |
| --- | --- | --- |
| 入口 | 视图页签「表单」 | 同上，无权限时；或编辑态里点「分享表单」后的预览 |
| 顶部 | ← 分享表单 ⋮ | ← 分享表单 ⋮ |
| 主体 | 封面图 + 标题卡（可编辑）+ 题目卡（可编辑标题/描述/控件） | 封面 + 白色卡片（标题 + 说明）+ 字段卡片（只读题面 + 可填控件） |
| 底部 | 排序 / 样式 / 设置 / 完成 + 「插入题目」 | 固定「提交」按钮 |
| 右下 | — | 铅笔 FAB（有权限 → 回编辑态） |

表单字段卡片：`01 老师 *` + 描述 + 控件；`02 附件` + 「+ 点击上传图片/文件」虚线框；`03 日期` + 日期控件。
必填用红色 `*`；题号 01/02/03 是**视觉序号**，不是字段名。

**本轮口径**：我们默认进**填写态**（只读文档里唯一的写入面），不做编辑态（编辑题目属文档编辑，走桌面或后续「编辑视图」入口）。

## 6. 手机适配规律（我们照抄的 8 条）

1. **信息分层靠「页签 + 工具行 + 列表」三段**，不塞抽屉、不弹大菜窗。
2. **首列固定 + 横向滚动**是表格在小屏的唯一可行解；可见列 2~3 个、其余滑动。
3. **分组是默认能力**（按日期/单选），组头带「N 条」+ 折叠，是长表在手机上的可读性来源。
4. **卡片是表格的替代展示，不是另一套数据结构**；两者共享筛选/排序/分组。
5. **配置面板贴底、页签切换、改完即生效、无保存按钮**（移动端不做「应用」二次确认）。
6. **记录详情用整页而不是浮层**，因为字段多且要翻页；底部只留一个主操作。
7. **主操作永远在拇指区**：提交 / 加号 / 翻页都在屏幕下半。
8. **颜色只做语义**：单选 chip 一色一类、条件填色整行、选中态淡底 —— 与我们的「主色只做锚点」一致。

## 8. 复刻方案（P0）

### 8.1 范围
- 做：**表单（填写）+ 内容（表格/卡片）**、视图页签、视图配置面板（筛选/排序/布局三页签，本轮布局可用、筛选排序只读展示）、视图列表、记录详情（只读）。
- 不做：看板/画册/日历/甘特（core 有类型，移动端后续开）；表单编辑态；分享/导出；评论。

### 8.2 状态与只读口径
| 入口 | 行为 |
| --- | --- |
| 打开文档 | **只读**（沿用 261023 定稿）；顶部「只读」徽标 |
| 默认页签 | **表单（填写）**；提交是只读文档里**唯一**写路径（新增记录，不改既有数据） |
| 内容页签 | 表格/卡片均只读：无「+ 添加」、无行内编辑、无字段菜单的编辑项 |
| 记录 | 点行/卡片 → 只读详情页（1/N 翻页） |
| 提交 | 校验必填 → 落本地记录（正文写回，走 store 写入 + 下一轮同步）→ toast + 计数 |
| 视图配置 | 布局切换**按「本机视图」处理**（建议，见 §10-Q2）；筛选/排序只读展示 |

### 8.3 布局配置（落到 BitableView 的新字段，或设备本地，取决于 Q2）
```ts
// 表格视图的「记录展示方式」，命名待定，语义同钉钉
type BitableRecordLayout = {
  mode: "table" | "card";        // 记录展示方式
  columns: 1 | 2;                // 卡片布局方式（不做 3 列）
  cover: boolean;                // 显示封面（取附件字段的图片）
  cardTitleFieldId?: string;     // 主标题（默认第一个字段）
  cardSubtitleFieldId?: string;  // 副标题（可空）
  cardFieldIds: string[];        // 展示字段（顺序 = 卡片内顺序）
};
```
> core 里 BitableView.form 已有字段选择与描述的既有形状可参照；grid 的 rowHeight/columnOrder/hidden 已是同层配置。

### 8.4 交互与几何（样机已实现）
- 顶部：← 标题/表名(只读徽标) ⋯（52px）→ 视图页签（46px，白底胶囊选中）→ 工具行（40px）。
- 表格：列宽 46 / 84 / 190 / 84（412 视口下正好露出「序号+类型+内容」，日期半露提示可滑）；行高 46；组头 33。
- 卡片：单列间距 10、卡片内 label 12px + 值 14px；2 列改上下排布；3 列只留主字段。
- 表单：封面 126 + 白色卡片（上移 26 压封面）+ 字段卡（标题 15/500 + 描述 12 + 控件 46）+ 底部提交条 48。
- 动效只用 250ms ease-out 入场（面板/详情页），状态切换瞬时（与 DESIGN 一致）。
