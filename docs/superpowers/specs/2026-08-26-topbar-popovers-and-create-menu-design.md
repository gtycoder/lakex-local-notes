# 顶栏弹框与新建菜单布局修复设计

## 目标

修复桌面端工作空间下拉、云同步状态两个弹框的定位和点击关闭问题，并让目录栏较窄时的新建菜单完整可见。

## 现状与根因

资料库和小记工作区采用 keep-alive，同时挂载两份顶栏。`App.tsx` 将包含状态的 `DesktopTopBarLeading` React 节点同时传入两个工作区，因此 `.sync-status-button` 和工作空间按钮各有两个实例。共享 ref 最终可能指向隐藏工作区的实例，其 `getBoundingClientRect()` 为零，弹框便落到左上角。顶栏菜单的外点关闭还通过全局 CSS selector 找按钮，两个实例存在时命中不确定。

## 方案

1. 不改变 keep-alive 和工作区结构。
2. 为顶栏菜单维护真实的 workspace wrapper / more wrapper ref，并使用 wrapper 作为外点关闭边界；弹框坐标始终从当前可见 wrapper 或按钮计算。
3. 对同步弹框增加可视锚点选择：优先选择布局中可见且尺寸有效的同步按钮，避免隐藏副本覆盖共享 ref；窗口尺寸变化或工作区切换后重新计算坐标。
4. 同一触发按钮再次点击关闭，Escape 和点击弹框/触发器之外关闭。
5. 新建菜单保留三项和副标题，将菜单项 `min-height`、padding、字体间距收紧；菜单通过 portal 使用固定定位，并根据侧栏实际矩形计算宽度和左边界，确保窄目录栏时不会被文档区覆盖。

## 不做的事情

- 不重构两个工作区的 keep-alive 架构。
- 不修改同步业务逻辑、数据模型或菜单功能。
- 不为旧数据增加兼容逻辑。

## 验收标准

- 工作空间下拉出现在工作空间按钮下方，不覆盖窗口左上角交通灯。
- 云同步状态弹框出现在云图标下方，且不因隐藏工作区实例而跳到左上角。
- 点击顶栏触发按钮可稳定打开/关闭弹框；点击目录栏、编辑区或其它弹框外区域可关闭。
- 窄目录栏打开新建菜单时，三个选项及副标题完整显示，不被目录栏或右侧区域裁切。
- `npx tsc --noEmit`、相关 Vitest 测试和生产构建通过。
