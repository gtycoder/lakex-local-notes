# 图标库迁移判定（261116 · 图标三线合并）

> 输入：`docs/icon-migration/A-official.md`（IconPark 官方能力/许可/打包）、`B-inventory.md`（仓内替换面清点）、`C-poc.md`（24px 视觉实测与工程接入 POC）。
> 本文只做合并判定，细节与证据看那三份；所有数字均为实测，复现命令见各文档附录。

## 0. 结论

1. **不把 IconPark 作为图标源引入**（全量、部分都不建议现在做）。
2. 若目标是「补齐缺失图标 / 纳管自绘图标」：**只挑单个 SVG 抄进仓库**（Apache-2.0 允许），不引运行时依赖 —— 这样自动继承 `svg.lucide{stroke-width:1.75}` 的单一来源。
3. 若确实要全量替换：**先由用户裁决改红线**（AGENTS §3#14「图标只用 lucide」+ §3#22「Lucide 维持唯一图标源」），再按 B0 试点（设置页 52 点）→ go/no-go，全量估 **8~15 人日**（约一半在视觉核验），并预留一个 release 的回滚窗口。

## 1. 三条硬阻断（技术/结构层，非审美）

| # | 阻断 | 证据 |
| --- | --- | --- |
| 1 | **上游已冻结** | `bytedance/IconPark` `archived=true`，最后 push 2023-02-24，最后 release v1.3.0 / 2021-02-15，799 open issue；npm `@icon-park/react` 最新 **1.4.2 / 2022-07-04**（4 年 4 个月未更新）。官网（© 2026）与开源包已分叉 |
| 2 | **打断描边单一来源** | 唯一来源 = `src/styles/app/base.css:27` `svg.lucide{stroke-width:1.75}`；IconPark 渲染 `span.i-icon > svg`（**svg 无 class**）⇒ 该规则失效、**29 条 `> svg` 直系选择器**全部失配、另引入 `.i-icon` 全局类族 + 4 主题 = 第二套样式范式 |
| 3 | **几何不 1:1** | 24px 实显 4× 设备像素实测：10 对高频图标**仅 4 对逐像素一致**（Plus、Chevron×3），平均墨迹覆盖偏差 **9.2%**，最差 **X +32%（墨迹盒 14→18px）**，Pencil/Search +22%，**Search 视觉中心上移 1.05px**。换算 `stroke 3.5@48 = 1.75@24`（用默认 4 会重约 13%），且需逐图标 size 校正（X 等效系数 0.78） |

同时撞 AGENTS 两条红线：§3#14（单图标源 / 单视觉几何）、§3#22（四问①无已验证痛点、②第二套样式范式不通过；「Lucide 维持唯一图标源」）。

| 项 | 数字 |

| 唯一图标 | **213 个** |

| 头部集中度 | **15 个核心几何图标（Plus/X/Check/Chevron*/Search/Trash…）= 435 点 = 49.2%**，跨 128 文件 |

## 3. 换不掉的面（迁移必然只覆盖一部分）

- **内核 vendor 215 个 symbol** + 2 个必须留在内核 sprite 的自定义卡图标（`noteRef` / `lockedText`）—— 属内核契约，不动。
- Drawnix / Univer 第三方图标、`kitchen-iconfont` 字体图标、品牌启动标记 —— 不动。
- **目录节点图标是数据不是组件**（`tree_nodes.icon` ≤16 字符、`n:<id>` 方言、17 个语雀插画被测试钉死）—— 迁移不得触碰（AGENTS §3#25②）。
- emoji 只作为数据存在于 `lakeEmojis`/`emojiZhKeywords` 数据表，不属图标层。

## 4. 成本与门禁

- 视觉基线强制重烤：桌面 **42 态** + 移动 **10 态** + 多维表 **3 态**。
- 单份桌面快照里 **12426/21794 = 57%** 的指纹行是裸 SVG 图元（`svgraw$*`）⇒ 重烤不能只看 exit code，必须人眼判读。
- **ui-metrics 实测不统计 SVG**（此前任务表述有误）；真正钉死图标的是快照 + 4 处测试硬编码：`mobileBitableViewer.test.ts`（钉 3 个 `lucide-*` class）、`sidebarRendering.test.ts`（`vi.mock("lucide-react")` 会变成"假通过"）等。

## 5. 已知坑（做之前必须知道）

1. `AboutSection` / `MaintenanceSection` / `useSettingsPanelScope` **3 处把 lucide `Image` 别名成 `Info`** 当设置分组图标 ⇒ 机械映射会把「信息」换成「图片」。
2. `sidebarRendering.test.ts` 的 `vi.mock("lucide-react")`：换库后测试仍绿但实际图标没渲染 = **假通过**，必须先改测试再换。
3. 58 处未传 `size` ⇒ IconPark 默认 `1em`，会系统性缩水。
4. IconPark 的"自定义图标"（官网项目管理上传）只做颜色跟随，**不承诺四主题**；四主题要靠 `@icon-park/compiler` 本地编译，且上传路径依赖登录/联网 SaaS（每账号 3 项目、终止后 60 天删数据）⇒ 不能当构建依赖。

## 6. 三条路径的判定

| 路径 | 判定 | 前提/代价 |
| --- | --- | --- |
| A. 全量替换成 IconPark | **不建议** | 需改两条红线 + 8~15 人日 + 42/10/3 态重烤 + 214 条映射表 + 吃掉冻结 4 年的上游 |
| B. 部分替换（只换 lucide 这 178 文件，自绘 19 文件/48 处内联 SVG 另议） | **仅当你裁决改红线** | 先 B0 试点（设置页 52 点 / 11 文件）→ go/no-go；建唯一适配层（IconProvider，strokeWidth=3.5）→ 214 条映射 + 光学校正 → 迁 9 条 `svg.lucide` 与 29 条 `> svg` → 补 58 处 size → 门禁重烤 → 保留 lucide 一个 release 做回滚 |
| C. 不换库，只抄单个 SVG 资产（推荐，若确有缺失/自绘需求） | **推荐** | 不引依赖、不动渲染结构、自动吃 1.75 单一来源；许可允许（Apache-2.0，无需署名但建议在 NOTICE 记来源）；成本按图标个数线性 |

## 7. 下一步（待用户裁决）

- 若走 C：给出「需要自绘/补齐的图标清单」（当前已知 13 个内联自绘文件 + 4 个 IconPark 无对应的 lucide 图标），逐个落成仓库内 SVG。
- 若走 B：先做 B0 试点（设置页 52 点），试点同时验证 3 件事：适配层能否复刻 1.75 几何、42 态里设置类 9 态重烤流程、`vi.mock` 类测试改法。
