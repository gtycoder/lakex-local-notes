# 浮墨笔记（flomo）调研：小记可借鉴能力与「独立标签管理」方案

> **文档性质**：调研 + 方案建议，不是规格，也不改代码。结论经用户确认后，再把稳定口径沉淀进 `QUICK-NOTES-SPEC.md` / `docs/HANDOFF.md`。
>
> **调研方式**：Edge 浏览器登录态只读浏览 `https://v.flomoapp.com/mine`（未新建、修改、删除任何 flomo 笔记/标签），并核对官方帮助中心；本地仅只读核对小记实现与测试。本文所有 flomo 行为均来自 2026-10-23 的实测或官方文档，官方文档与线上不一致处已标注。

## 0. 结论先行

1. **flomo 把标签当一等公民**：多级标签（`#标签/子标签`）、重命名、移动到其他父级、置顶、标签图标、拖拽排序、标签搜索、无标签发现、删除（仅移除标签 / 标签和笔记一起删）。标签同时是正文语法，不是独立文件夹。
2. **我们小记的标签目前只是内容字段**：`content.tags: string[]`，能力止于展示、单选筛选、单条增删、派生计数；没有重命名/合并/删除/颜色/层级/排序，HANDOFF 也明确记了「标签下拉未做标签管理」。
3. **建议做「独立的标签管理界面」，但第一版不要引入独立标签表或新的同步 sidecar**：继续让 `content.tags` 做唯一真相，重命名/合并/删除用「先出计划、再批量重写受影响小记、最后统一同步一次」实现。这样不动 schema、不动 Manifest、不碰旧端兼容，风险最低；颜色/排序/层级等目录元数据留到第二阶段再定。
4. **除了标签管理，flomo 还有 4 类能力值得小记借鉴**（按建议优先级）：
   - **回顾**：每日回顾（范围/时间/条数/提醒）、随机漫步；
   - **检索**：无标签、有图片、时间范围、标签包含/排除等快捷筛选；
   - **捕获**：桌面小组件、分享入口、长按快捷方式、语音转写；
   - **AI**：AI 洞察、相关笔记、AI 找一找（放后）。
5. **做标签管理前先修 3 个现有缺陷**：
   - 桌面预览勾选待办会**清空该条小记的全部标签**；
   - 缺正文恢复会把**含空格的标签拆坏**；
   - 类型筛选生效时点卡片标签，会形成**用户看不见的 AND 条件**。

## 3. 标签体系深挖（本次调研重点）

### 3.1 标签是什么

- 标签写在正文里：`#标签`，多个标签用空格分隔；多级用 `#标签/子标签`，例如 `#Books/Different/营销近视症` 会形成三级。
- 标签也可当正文内容使用，位置不限（开头、结尾、中间都可以）。
- 规则（官方）：
  - 不要在标签里用 emoji 和特殊字符（会导致无法查询）；
  - 英文建议用下划线连接，如 `#Apple_seed`；
  - 标签之间必须空格分隔，否则会被识别成一个标签。
- 标签的“身份”就是标签名：官方没有暴露标签 ID；重命名、移动、删除都通过改写标签名或标签路径完成。

### 3.2 管理入口与操作（线上实测 + 官方文档）

**侧边栏**
- 「全部标签」可展开/收起标签列表；标签行显示 `#` 图标、名称、笔记数；行悬停出现 `···`。
- 「全部标签」右侧有**标签搜索**与**排序**入口。
- 标签行左侧的 `#` 图标可点开「编辑名称/图标」；官方说明该图标为 PRO 权益（网页端与 Android 可换）。

**标签行 `···` 菜单（实测）**
1. **置顶**；
2. **编辑名称/图标**；
3. **移动到…**；
4. **删除标签**。

**编辑名称/图标**
- 弹层 = 图标位 + 名称输入 + 保存；
- 提示「使用 标签/次级标签 格式创建多级标签」，可直接通过改名把标签搬到另一个父级下；
- 图标位可更换（官方文档：PRO 权益）。

**移动到…**
- 弹窗标题「移动标签」；
- 输入框「搜索，或输入一个新的上级」；
- 当前层级显示「顶级（无上级） · 当前位置」；
- 底部显示「当前标签 #测试1」，可取消 / 确定移动。

**排序**
- 弹窗「标签排序」：拖拽手柄 + 「恢复默认」+ 保存 / 取消；
- 官方文档写的是「按字母顺序 + 想改顺序就在标签前加数字，拖动和其他排序方式尚在思考」，**线上已经有拖拽排序** ⇒ 文档滞后，线上为准。

**删除**
- 官方：选择「删除」后，可选择：
  - **仅移除标签**（保留笔记）；
  - **删除标签和笔记**（相关笔记移入回收站）。
- 我们的建议：第一版只做「移除标签、保留笔记」；「连笔记一起删」风险高，且与「小记不设回收站」的现状冲突。

**未加标签**
- 官方：点击搜索框会弹出「无标签」选项；
- 线上搜索面板有「快捷搜索」区域，实测当前账号只展示「那年今日」，官方文档列出「有图片 / 有音频 / 有链接 / 无标签 / 去年今日 / 自定范围」，以文档为准（可能受数据/版本影响）。

### 3.3 值得注意的设计取舍

1. **标签名即身份，管理动作 = 改内容**
   - 好处：零额外数据模型，标签天然随笔记同步，不会出现“标签目录与笔记不一致”；
   - 代价：重命名/合并/删除都要批量改写笔记；跨端要等同步；冲突时可能出现“改了一半”。
2. **删除有明确的两档语义**：仅移除标签 vs 连笔记一起删。这是标签管理里最容易误伤的地方。
3. **没有看到显式“合并标签”入口**：官方文档只讲重命名/移动/删除；实际整理时可以把 A 改名成 B（或 `#B/A`）来达到合并/收编效果，但**官方没有承诺同名会自动合并**。我们做的时候建议**显式提供“合并到…”**，比让用户猜改名更安全。
4. **核心标签管理免费，图标是 PRO**：flomo 把“组织能力”放开，把“装饰/高级能力”收费；这与我们“个人本地优先”的定位一致——标签管理不该做成付费点。
5. **与文件夹的区别**：flomo 只有标签，没有笔记本/文件夹；我们已有笔记本树，小记是独立时间线，所以**不应该把标签做成第二套文件夹**。

### 4.3 现有缺陷与风险（已核对代码）

1. **【数据丢失】桌面预览勾选待办会清空标签**
   - `togglePreviewTask` 调 `native.updateQuickNote` 时只传 text/body/draft/图片，没有传 tags；
   - `normalizeQuickNoteContent(..., tags = [])` 缺省是空数组；
   - 结果：该条小记的 `content.tags` 被写成 `[]`。
   - 证据：`src/components/app/QuickNotesWorkspace.tsx:549-555`、`src/core/quickNoteModel.ts:67-84`、`electron/quickNotes.ts:570`。
   - 建议：UI 显式传 tags；同时主进程把“未传 tags”解释为“保持原 tags”，而不是清空（但需检查所有调用点语义）。
2. **【数据损坏】缺正文恢复拆坏含空格的标签**
   - 搜索账本把 tags 存成空格拼接；恢复时 `split(" ")` 重建数组；
   - 标签允许内部空格（`aaa   bbb` 归一成 `aaa bbb`），会被拆成两个标签。
   - 证据：`electron/quickNotes.ts:286-290`。
3. **【隐藏条件】类型筛选下点标签形成 AND**
   - 类型筛选生效时标签条/下拉隐藏，但卡片上的标签仍可点；`onFilterTag` 只改标签筛选，不清类型筛选；
   - 用户看到“筛选出来的结果变少但不知道为什么”。
   - 证据：`src/components/app/QuickNotesWorkspace.tsx:900`、`:1099`、`:851-858`。
4. **移动端 schema 版本门**：新增表/列必须 `MOBILE_SCHEMA_VERSION + 1`，DDL 走 `executeSet` 批量；漏 bump 会静默缺列（`src/mobile/data/schema.ts:30`、`:312`）。
5. **同步契约测试不覆盖 tags**：`electron/quickNotesSyncContract.test.ts` 只传 text/draftId/stagedImageIds；跨端标签往返没有护栏。
6. **标签筛选不走索引**：两端都是已加载列表上的 JS 过滤；若未来移动端分页，计数口径会变。

## 5. 「独立标签管理」建议方案

### 5.1 先定义“独立”

建议把“独立”限定为**独立的管理界面/入口**，而不是**独立标签实体**：

- **保留** `content.tags` 作为唯一真相（single source of truth）；
- 管理动作 = 对受影响小记做批量内容重写；
- 不新增独立标签表、不新增同步 sidecar、不改 `.qnote` 版本、不改 Manifest。

理由：
- 现有标签已经随小记内容同步，跨端天然一致；
- 新增标签表/ sidecar 会牵动 Manifest 严格版本、旧端丢字段、GC keep set、冲突策略，成本远高于收益；
- 我们的标签是结构化字段，不像 flomo 是正文里的 `#tag`，批量重写更安全、可控。

> 如果后续确实需要“空标签 / 颜色 / 置顶 / 排序 / 层级”这类**目录元数据**，再单独评估“设备本地元数据”或“sidecar 同步”。第一版不做。

### 5.2 P0：标签管理 MVP（桌面 + 移动）

**入口**

- 桌面小记页：
  - 页头/标签条右侧「标签管理」按钮（**即使当前没有标签也要可见**，空态可进入）；
  - 标签行 `···` → 「管理标签」；
  - 标签下拉底部「管理标签…」。
- 移动端：
  - 首页小记筛选条右侧「管理」或更多菜单入口；
  - 设置页「小记 → 标签管理」作为兜底入口（保证零标签时也能进）。

> 入口不要只挂在“标签下拉”里：当前空态/类型筛选下标签条会整体不渲染，用户会找不到管理入口。

**列表与搜索**

- 展示：标签名、关联小记数、最近使用时间（可选）、是否置顶（可选）；
- 排序：默认“计数降序 + 名称”；可选“最近使用 / 名称”；
- 搜索：按标签名模糊过滤；
- 无标签：单独一行/分组，显示数量，点击筛选；
- 空态：说明“标签来自小记正文，保存小记时添加”。

**操作**

1. **重命名**
   - 输入新名称（同一套归一/长度/保留名校验）；
   - 预览：将影响 N 条小记；
   - 执行：批量把旧名替换为新名；若新名已存在，提示“将合并到已有标签”（见下）。
2. **合并**
   - 选择一个或多个源标签 + 一个目标标签（或新建目标名）；
   - 预览：影响条数、合并后计数；
   - 执行：把源标签条目的 tags 中旧名替换为目标名，去重；
   - 合并后源标签自动消失。
   - **建议显式提供**（flomo 没看到显式入口，但这是用户最需要的整理动作）。
3. **删除**
   - 仅“从所有小记移除该标签”，保留小记；
   - 二次确认，写明“将影响 N 条小记，不会删除小记”；
   - 第一版不做“删除标签和笔记”。
4. **可选的轻量能力（建议后置）**
   - 置顶：只影响当前设备的列表顺序（需要本地偏好表；跨端不一致要在 UI 说明）；
   - 自定义排序：同上；
   - 标签图标/颜色：与设计系统“主色是锚点不是装饰”冲突，且 flomo 是 PRO 装饰能力；**不建议第一版做**；
   - 多级标签：若做，建议只做“名称含 `/` 的树形展示 + 移动到父级”，不新增数据结构；但需要真实验证“小记是否需要第二套层级”（我们已有笔记本树）。

**执行与一致性**

- 先出**计划**（旧名→新名、受影响 id 列表、条数），再让用户确认；
- 批量写：逐条读取 `.qnote` → 改 tags → 写回（保留 `updatedAt` 逻辑已有）；失败要能继续/回滚，至少给出“成功 N / 失败 M”；
- 写完后**统一触发一次完整小记同步**，不要逐条调用单条推送（Manifest 单文件覆盖写、无 CAS）；
- 幂等：重复执行“把 A 改成 B”应无副作用（A 已不存在则跳过）；
- 冲突：批量期间他端编辑同一篇 → 远端覆盖本地、本地留档；管理结果可能部分回滚，需要在完成后提示“有 N 条被远端更新覆盖”；
- 执行后刷新：列表、标签条、选择器、FTS/索引、正在筛选的标签状态（若当前筛选的标签被改名/删除，回退到“全部”）。

**移动端特别项**

- 若只做内容重写，**不需要加表/加列**，可避免 schema 版本门；
- 若做置顶/排序/图标等本地元数据，新增表必须 `MOBILE_SCHEMA_VERSION + 1`，DDL 放 `baseSchemaStatements`（不依赖读状态）或 `collectSchemaStatements`（依赖读状态），走 `executeSet`；
- 批量重写在移动端会 N 次桥调用，需评估 1000+ 条小记的耗时；可考虑主进程/原生批量接口，但第一版先用现有逐条写 + 进度提示。

### 5.3 数据模型决策（建议写进规格）

| 方案 | 内容 | 优点 | 风险 | 建议 |
|---|---|---|---|---|
| **A. 内容派生 + 批量重写** | 标签仍在 `content.tags`；管理只做批量改写 | 不动 schema/Manifest；跨端自然一致；实现小 | 批量写/冲突/性能 | **第一版采用** |
| B. 独立标签表（本地） | 新表存标签目录/颜色/排序 | 查询快、可存元数据 | 与内容双真相；跨端不同步；迁移 | 只用于“设备本地偏好”，不做标签身份 |
| C. 独立标签表 + sidecar 同步 | 标签目录进 `quick-notes/` 新对象 | 真正跨端元数据 | Manifest 严格版本/旧端丢字段/GC/keep set/冲突，成本高 | 暂不做 |

### 5.4 测试与护栏

- `quickNoteTags`：重命名/合并计划、保留名、空名、长度、20 个上限、含空格/Unicode；
- 批量写：受影响条数、幂等、失败继续、`updatedAt` 不刷新、正文/图片不变；
- 回归：待办勾选不清标签、缺正文恢复不拆含空格标签、类型筛选点标签行为一致；
- 同步契约：跨端 tags 往返 + 冲突（现有契约测试不覆盖 tags）；
- 移动端：schema 升级测试（若加表）、批量操作性能；
- UI：空态入口、重命名/合并/删除确认、筛选状态回退；
- 门禁：`tsc` + `vitest` + `git diff --check`；改样式再跑 `ui-metrics` / 层围栏；移动端改动跑 mobile 门禁。

## 7. 需要用户拍板的问题

1. **“独立标签管理”指独立管理界面，还是独立标签实体？**
   - 建议：独立管理界面 + 内容派生；不要独立标签表。
2. **第一版范围**：重命名 / 合并 / 删除 三项够不够？是否同时做置顶、排序、搜索？
   - 建议：重命名 / 合并 / 删除 / 搜索 / 计数；置顶排序后置。
3. **标签元数据是否要跨端同步？**
   - 建议：第一版不做元数据；若做置顶/排序，先做设备本地并在 UI 明说“不同步”。
4. **删除标签的语义**：只移除标签（推荐）还是提供“连笔记一起删”？
   - 建议：只移除标签；不碰笔记删除。
5. **是否要在同一批做“每日回顾”和“移动端筛选补齐”？**
   - 建议：标签管理 MVP 单独一批；回顾/筛选各自立项，避免一批太大。
6. **移动端是否与桌面同批？**
   - 建议：同批做“管理入口 + 重命名/合并/删除”，但移动端没有页内搜索/类型筛选，先保证管理入口可用。
7. **是否需要多级标签？**
   - 建议：先不做；如果做，只做名称含 `/` 的展示与移动，不新增数据结构。
