# 多维表（数据表）产品文档（260919）

> **本文性质**：产品文档。基于 **2026-09-19 对两个真实实现的实机走查** —— ① 语雀云端「数据表」（§1.1–1.8，源码级 DOM 核对 + 逐项交互）、
> ② 钉钉多维表（§1.9，多数据表形态）—— 给出我们自研多维表的产品范围、数据模型口径、交互规范与验收清单。
> **与既有文档的关系**：技术选型/存储/同步归 `docs/SHEET-BITABLE-DESIGN-260918.md`（本文不重复论证，只在其结论上细化「产品是什么」）；
> 表格（`kind = sheet`）见同文档 §3.1 与 `docs/FORTUNESHEET-FEASIBILITY-260919.md`。
>
> **证据等级约定**：`[实测]` = 本次在真实云端页面上点过、看过 DOM 的；`[推断]` = 由实测结构推导、未直接验证的；`[决定]` = 产品结论。

## 0. 一分钟摘要

1. 语雀云端把「表」分成**两种互不相同的文档类型**，同在知识库目录树里 `[实测]`：
   - **表格**（电子表格，A/B/C 列 + Sheet1 标签 + 冻结/行高工具条）——对应我们的 `kind = sheet`；
   - **数据表**（记录式数据库，字段 + 记录 + 多视图）——对应我们的 `kind = bitable`，即本文主角。
2. 云端「数据表」= **字段层（18 种类型）+ 记录层（记录详情含一篇 Lake 正文）+ 视图层（6 种视图）** 三件套，外面挂一整套工具栏（筛选/分组/排序/行高/搜索/统计/生成表单）。
3. **这套能力不在我们 vendor 的内核里**`[实测]`：`lakex-table-*`、`larkui-icon`、`LakeTableNextEditor`、中文「数据表」在 `vendor/lakex-doc-react/src/components/lakex/lakex.js`（v1.99.0）中**一处都搜不到**，而 `ne-engine`、「代码块」「高亮块」「分栏」都在。⇒ 表是**外层应用**，编辑器才是内核。
4. 但**记录正文用的正是同一个 Lake 内核**`[实测]`（记录详情里是完整的 `ne-editor` + 工具栏 + 插入卡片）。⇒ 我们该自研的只有「字段/记录/视图」这一层，编辑器不用重造。
5. **首期范围（用户 260919 定稿，详见 §6.1）**：**一个文档多张数据表** + 表格视图 + 表单视图 + **7 种字段**（文本 / 数字 / 单选 / 多选 / 日期 / 图片和附件 / 关联占位）+
   筛选 / 排序 / 行高（多档）+ 记录详情表单；**不做**记录正文、统计汇总、看板等其余视图、分享收集、AI、导入导出、自动化。
6. 第二个参考实现（§1.9）：**钉钉多维表**只值得抄「一个文档挂多张数据表」这一条形态；它的字段体系（30 种常规 + 一组 AI 字段）、AI 筛选/填色、多级分组、仪表盘等都**不抄**
   —— 用户 260919 原话：「钉钉只值得抄一下多数据表，其余的字段太多了」。

## 1. 实机走查：语雀云端「数据表」全貌

> 走查对象：用户知识库 `03-交易` 下的「无标题数据表」，初始状态 = 1 个表格视图 / 3 个字段（文本、单选、日期）/ 3 条空记录。
> 走查结束时已把页面恢复至初始状态（前后截图字节数一致，167,634 B）。

### 1.1 文档类型与入口

- 「数据表」与「表格」「文档」**平级挂在同一知识库目录树**，是一个独立文档，不是嵌在 Lake 文档里的卡片`[实测]`。
- 文档头部是普通文档头：标题、`已保存` 状态、收藏/关注/分享/导出/页面视图切换`[实测]`。
- 打开即进编辑态（无只读预览概念），默认落在**第一个视图 = 表格视图**`[实测]`。

### 1.2 视图层（多视图是这东西的灵魂）

视图标签栏 = `表格视图` + `⋯` + `+` `[实测]`：

| 交互 | 内容 |
|---|---|
| 视图 `⋯` 菜单 | **重命名视图 / 复制视图 / 删除视图**（共 3 项，无「切换视图类型」） |
| `+` 新增视图 | 弹出 6 种视图类型（见下表），选中即新建一个视图标签页 |

新增视图的 6 种类型（含官方副标题）`[实测]`：

| 视图 | 官方描述 | 性质 |
|---|---|---|
| **表格视图** | 规范化存储和展示数据 | 网格；v1 必做 |
| **看板视图** | 任务流转一目了然 | 按某字段分组为泳道；需要「分组字段」 |
| **画册视图** | 适合展示图片类数据 | 卡片墙，以图片字段为封面 |
| **日历视图** | 轻松搞定日程安排 | 以日期字段铺日历 |
| **图表视图** | 查看和分析数据 | 统计图（计数/求和等） |
| **表单视图** | 像问卷一样收集信息 | 另开一套表单编辑器（§1.7） |

> `[实测]` 视图是**数据之上的一层投影**：删掉「表单视图」后回到表格视图，字段与记录**一条没变**。
> 这是关键架构结论 —— **字段与记录属于文档，视图只是配置**，两者不能混在一个结构里。

### 1.3 字段层（18 种类型）

**字段编辑弹窗**（列 `⋯` → 编辑列，或「表格配置」里字段 `⋯` → 编辑）`[实测]`：

```text
数据表列名  [ 文本                    ]
列类型      [ 文本 ⌄ ]  ← 展开为 18 种，分「基础 / 高级」两组
默认值      [ 请输入                   ]
                    [ 取消 ] [ 确定 ]
```

完整类型表 `[实测]`：

| 组 | 类型（按界面顺序） |
|---|---|
| **基础（14）** | 文本 · 数字 · 单选 · 多选 · 日期 · 人员 · 图片 · 附件 · 复选框 · 链接 · 邮箱 · 手机号码 · 评分 · 进度 |
| **高级（4）** | 创建人 · 创建时间 · 修改人 · 修改时间 |

`[实测]` 注意：**没有公式字段、没有关联/汇总字段**（飞书多维表有的这两类，语雀这版没有）。

**列头 `⋯` 菜单（10 项）**`[实测]`：

```text
编辑列 / 复制列          ← 组 1
向左插入列 / 向右插入列    ← 组 2
按本列分组 / 按本列筛选    ← 组 3（视图级操作，直接落在当前视图上）
升序 / 降序 / 高亮重复值   ← 组 4（视图级）
删除列                  ← 组 5
```

**「表格配置」面板**`[实测]`：字段清单，每行 = 拖拽手柄 + 类型图标 + 名称 + 眼睛（显示/隐藏）+ `⋯`（编辑 / 删除）。
表头末尾还有一个 `+`，点开是同一个字段类型选择器 ——「加列」有三个入口（表头 `+`、列菜单「向左/向右插入列」、记录详情里「新增字段」）。

### 1.4 记录层（记录 = 一段结构化值 + 一篇 Lake 正文）

行的构成`[实测]`：`行号` + `拖拽手柄`（排序）+ `展开按钮`（打开记录详情）；表格最后一行是 `+`（添加记录），底部是 `N 条记录`。

**记录详情抽屉**（点行内展开按钮）`[实测]`，这是整个产品里最值钱的一块：

```text
[链接] [上一条⌃] [下一条⌄] [⋯] [关闭]      ← 顶部操作条
未命名记录                                  ← 标题 = 主字段（首列文本），未填则显示「未命名记录」
  文本   [ 请输入              ]            ← 字段纵向表单（按字段类型给不同控件）
  单选   [ 请选择              ]
  日期   [ 请选择日期           ]
  + 新增字段                                ← 在这里就能加列
  点击输入正文内容                            ← 每条记录的富文本正文
```

- **正文区是一个完整的 Lake 编辑器实例**`[实测]`：DOM 里是 `ne-editor` + `ne-ui-toolbar`（含「插入卡片」按钮）+ `lark-mini-editor` / `EditorBase-module_editor` / `LakeTableTextEditor-module_textEditor`。也就是说**记录正文和我们的文档正文是同一套内核**。
- 顶部支持**上一条 / 下一条**连续翻阅记录`[实测]`。
- 抽屉右侧还有一个「展开/收起」按钮（`lakex-table-expand-record-direction`），即抽屉宽度可切换`[推断：由类名与图标推断]`。

### 1.5 视图级配置（工具栏）

工具栏（从左到右）`[实测]`：**表格配置 | 筛选 | 分组 | 排序 | 行高 | 搜索 ｜ + 添加记录 …… 生成表单**。
内部 DOM 里这些按钮有稳定 id：`#view-field-setting` `#filter` `#grid-group` `#sort` `#row-height` `#search` `#add-record` `#create-form`。

| 面板 | 实测内容 |
|---|---|
| **筛选** | 规则行 = `当 [字段▾] [操作符▾（如「开头是」）] [值输入框] ⋯`，另有「+ 添加筛选规则」「删除筛选」。**点开面板就会生成一条空规则**，工具栏按钮右上出现「1 个筛选」角标 —— 即筛选规则是**落在视图上的一等对象**，不是临时高亮 |
| **分组** | 面板只有一个「选择一列进行分组 ⌄」（空态），**无确定按钮**（选完即生效） |
| **排序** | 「选择一列进行排序 ⌄」+ 取消 / 确定 |
| **行高** | 低 / 中 / 高（三档，默认「低」，当前档打勾） |
| **搜索** | 浮动「查找」框：输入框 + 上一个 / 下一个（浏览器式查找，不是视图筛选） |
| **统计** | 在**表格底部每列**各有一个「统计」下拉（§1.6） |

### 1.6 单元格、选择与批量操作

- 单元格编辑器按字段类型给不同控件`[实测]`：单选 = 下拉（`lakex-table-dropdown-selector`），面板内是「可搜索或新建选项」输入框 + 已有选项列表（实测已有 `待开始` / `进行中` / `已完成`，带颜色），每项 hover 出 `⋯` 可改选项本身。日期 = 日期选择器（`请选择日期`）。
- `[实测]` 表头左侧复选框 = 全选记录；选中后行底色变浅蓝，底部文字从 `3 条记录` 变为 **`已选择 9 个单元格`**。
- `[实测]` 在选区上**右键** → `复制 ⌘C` / `粘贴 ⌘V` / `删除行`。**没有**独立浮出的「批量操作条」。
- `[实测]` 底部每列的统计下拉（文本列实测选项）：`不展示 / 记录总数 / 已填写数 / 未填写数 / 唯一数 ｜ 已填写占比 / 未填写占比 / 唯一数占比`（默认「记录总数」打勾）。单选列与日期列各自有「统计」入口`[实测：入口存在；具体选项未逐项展开]`。

### 1.7 表单视图（「生成表单」）

`[实测]` 点工具栏右侧「生成表单」**直接新建一个名为「表单」的视图标签页**并切过去，内容是表单生成器：

```text
[ 编辑表单 | 预览表单 ]                      ← 顶部分段控件        右上：[ 开始收集 ]
左：可用项 / (空)
    新建项：文本 数字 单选 多选 日期 人员 图片 附件 复选框 链接 邮箱 手机号码 评分 进度
右：表单画布：标题「表单」+「请输入表单描述」占位 + * 必填字段列表（1.文本 / 2.单选 / 3.日期）
```

`[决定]` 这东西对**本地优先、无服务端**的应用价值很低：它的核心是「生成一个可分享链接去收集外部填写」，我们既没有可公开的收集端点，也不该为此引入联网上传。**不建议做**（详见 §6 待决策 Q5）。

### 1.8 顺手记下的交互细节（做的时候会省事）

- 视图标签、列、记录都支持**拖拽排序**`[实测：DOM 上有 dnd 拖拽手柄与提示文本]`。
- 「数据表」内部把弹出层统一挂在 `lakex-workbench-global-modal-container` 上（筛选/分组/排序/记录详情抽屉都是它）`[实测]` —— 与我们已有的浮层体系是同一思路。
- 文档头部的保存状态是 `已保存`（自动保存，无手动保存按钮）`[实测]`。
- 空数据表在页面下半部还会露出语雀的**模板引导**（阅读书单 / 待办清单 / 新年计划 / 班级同学相册 / 更多模板）`[实测]`；我们不做模板库，但「空态给 2–3 个起步模板」是个便宜且有效的体验点`[推断]`。

### 1.9 第二参考实现：钉钉多维表（260919 实机走查）

`[实测]` 对象 = 钉钉文档「观点收集」（内含 5 张数据表）。本节只记 **我们可能用得上的基础能力**，钉钉的 AI / 自动化 / 分享 / 应用模式一律不做。

**最关键形态：一个文档 = 多张数据表**

- 左侧「数据」面板列出文档内的多个对象：`1财智复盘 / 1财智语音 / 资料文章收集 / 2文字AI / 3飞书群`，点击即切换；底部「添加/导入」可新增：导入 Excel / **数据表** / 收集表 / 说明文档 / 仪表盘 / **文件夹** / 智能体 / 数据连接中心。`[实测]`
- 顶部是文档级模块页签：`数据 | 自动化 | 应用 | 表单 | 表哥`。`[实测]`
- 每张数据表各自持有自己的视图页签与视图配置 ⇒ 结构是 **文档 ⊃ 数据表 ⊃（视图 / 字段 / 记录）** 三层。`[实测]`

**每张数据表的视图页签**（实测为 `表单 | 内容 | ⋯ | +`，"内容"= 表格视图；右上角另有「插件」= 排版打印）`[实测]`。

**新增视图的类型（8 + 2）**`[实测]`：

| 分组 | 项 |
|---|---|
| 视图 | 表格视图 / 看板视图 / 日历视图 / 甘特视图 / 画册视图 / **表单视图** / 透视表视图(新增) / 地图视图(新增) |
| 页面 | 查询页面 |
| 插件 | 排版打印 |

**字段类型：30 种常规 + 一组 AI 字段**`[实测]`：

```text
常规字段：文本 单选 多选 日期 数字 货币 人员 图片和附件 进度 链接 公式 按钮 流程
          勾选框 评分 电话 部门 群组 邮箱 行政区域 条码 身份证号 手写签名 地理位置
          富文本 查找引用 单向关联 双向关联 关联引用
AI 字段：信息提取 匹配分类 生成文本 图片和附件理解 快递物流查询 AI 听记总结 生成图片 创建 AI 字段
```

- `[实测]` 注意：钉钉把「**图片和附件**」做成**一个**字段类型 —— 与用户 260919 的决定完全一致。
- AI 字段区、按钮/流程字段、关联类字段（单向/双向关联、查找引用）都属于我们不做或后置的范围。

**工具栏与视图配置**`[实测]`：

| 项 | 钉钉实测 | 我们的取舍 |
|---|---|---|
| 工具栏 | `添加记录 ｜ 字段管理 ｜ 筛选 ｜ 按「日期」分组 ｜ 按 2 个字段排序 ｜ 行高 ｜ 填色`，右侧 撤销/重做/锁定/搜索/提醒设置/分享视图 | v1 做：添加记录 / 字段管理 / 筛选 / 排序 / 行高 /（搜索）。不做 锁定、提醒设置、分享视图 |
| 分组 | **多级分组**（可加多条）+ 每条单独升降序 + 「折叠所有 / 展开所有」；表格按组渲染（组头 = 字段名 + 组值 + 折叠箭头 + 组内统计入口） | v1 不做（放 v1.5；分组是看板的前置） |
| 排序 | 多条件，且**升降序选项随字段类型变化**（单选 = 选项顺序 / 选项逆序；日期 = 早→晚 / 晚→早） | v1 做（这条细节值得照抄） |
| 行高 | 常规 / 中等 / 高 / 超高 / 自定义(px) / 自动调整标题行高 | v1 可做（低成本） |
| 筛选 / 填色 | **AI 优先**：输入框提示「告诉 AI 你想看到什么」「描述哪些内容用什么颜色」，另配「添加条件 / 添加筛选条件组」 | 只做手动「添加条件」，不做 AI 入口 |

**表单视图**`[实测]`：左侧「可选题目（全部添加 / 全部移除）」+「新增题目」（基础题型 20 种、高级题型）；中间表单预览（题目序号 01/02/03 + 标题 + 可选「添加描述」）；右侧表单设置（谁必须填写 / 匿名填写 / 每人填写次数限制 / 提交总数限制 / 表单填写校验 / 限制填写时间 / 周期性填写 / 开启语音填表）；左上「填写表单」。

> ⇒ 我们要的就是它的**左（选题）+ 中（预览）+「填写表单」（应用内录入新增记录）**这三件；
> 右侧那一整列「填写规则 / 分享 / 催填」属于对外的收集能力，**不在 v1**。

**从钉钉看「还能补什么基础能力」**（结论，供 §3.3 使用）：

| 能力 | 判断 |
|---|---|
| 一个文档多张数据表（左栏列表 + 新建/重命名/删除/排序/切换） | ✅ **只抄这一条**（用户 260919 定稿） |
| 「图片和附件」合一字段 + 走资产管线 | ✅ v1 做（用户 260919 点名） |
| 钉钉的其余字段类型（勾选框/链接/电话/邮箱/评分/进度/货币/…） | ❌ 不要 —— 用户原话：「这些字段都不要，都是文本的扩展」 |
| 表单视图 | ✅ 做，但取**语雀形态**：填写后生成一行表格数据；钉钉那种「分享到群里填写」不做 |
| 行高多档（常规/中等/高/超高/自定义） | ✅ v1 做（用户 260919 确认） |
| 关联字段（单向/双向关联、查找引用） | ◻ v1 只落**占位类型**：能选到、能建列、不联动（用户 260919 确认） |
| 字段属性「必填 / 默认值」 | ✅ v1 做（表单录入要靠它，成本低） |
| 多级分组 + 折叠全部 | ⏸ v1.5 |

## 2. 与内核的关系（本次最重要的技术事实）

`[实测]` 在同一台机器上用同一份 vendor 产物做的比对：

| 搜索词 | 在 `vendor/.../lakex/lakex.js`（v1.99.0）中 |
|---|---|
| `lakex-table` / `viewer-grid` / `LakeTableNextEditor` / `larkui-icon` / `数据表` | **均无命中** |
| `ne-engine` / `代码块` / `高亮块` / `分栏` / `折叠块` | 命中 |

结论`[决定]`：

1. 云端的「数据表」是 lakex 体系里的**独立应用模块**（类名前缀 `lakex-table-*`、`lakex-viewer-grid-*`、`lakex-workbench-*`，图标走另一套 `larkui-icon`），**不在我们的闭源内核产物里，升级 vendor 也拿不到**（与 `SHEET-BITABLE-DESIGN-260918.md` §1.1 的结论一致，本次是独立的二次验证）。
2. 但 `[实测]` 记录正文用的是**同一个 Lake 内核**（`ne-editor`）。⇒ 我们要自研的边界很清楚：**字段/记录/视图/工具栏这一层**，编辑器与正文能力直接复用。
3. 云端的内部命名可以直接当我们的**实现参考系**（本地实测抓到的类名族）：
   `lakex-table-workbench-*`（工具栏）、`lakex-viewer-grid-*`（网格）、`lakex-table-view-setting-*`（字段配置）、`lakex-table-expand-record-*`（记录详情）、`lakex-table-record-desc`（记录正文）、`lakex-table-stats-*`（逐列统计）。

## 3. 我们的产品定位

### 3.1 三个真实场景（用来判断「该不该做」）

1. **清单/台账**：交易记录、持仓、观察池 —— 结构化字段 + 筛选排序 + 简单统计。
2. **进度管理**：任务/学习计划 —— 状态（单选）+ 日期（后期可加看板视图）。
3. **资料索引**：书单、链接收藏 —— 文本（链接直接贴文本）+ 图片和附件 + 多选（标签）。

> 用户已定口径：**大部分需求是结构化存储 + 简单公式**；真要「算得复杂」的场景挂附件用 Excel，不在这里实现完整 Excel。

### 3.2 与「表格（kind = sheet）」的分工

| 问题 | 表格（sheet） | 数据表（bitable） |
|---|---|---|
| 心智 | 一张电子表格：单元格就是数据 | 一批记录：每行是一条对象 |
| 适合 | 计算、公式、排版、临时台账 | 分类、筛选、状态流转、跨视图查看 |
| 结构 | 无字段类型，列即字母 | 字段有类型与选项，列是有名字段 |
| 视图 | 多 Sheet，单表 | 多视图投影同一份记录 |

`[决定]` 两者**都保留**（与语雀云端一致），新建时让用户自己选；不做「表格自动升级为数据表」这类转换（AGENTS §3 #7：不为假设需求做机制）。

### 3.3 v1 做什么 / 不做什么

**v1 做**（用户 260919 定稿）

- 新建「数据表」文档（目录树右键），与文档/表格/小记同管线（同步、回收站、历史、重命名、移动）。
- **一个文档内可含多张数据表**：左侧数据表列表（新建 / 重命名 / 删除 / 拖拽排序 / 切换），对齐钉钉形态（§1.9）。
- **表格视图**：字段增删改 / 拖拽排序 / 列宽 / 隐藏，记录增删 / 拖拽排序，单元格按类型编辑。
- **表单视图**：左侧选题（可选题目 + 新增题目）+ 中间预览 + 「填写表单」应用内录入并新增记录（**不含分享 / 填写规则 / 催填**）。
- 字段类型 **7 种**：**文本（主字段）· 数字 · 单选 · 多选 · 日期 · 图片和附件 · 关联（占位）**。
  - 「图片和附件」是**一个**类型（用户 260919：「图片也是一种常用的附件」），值 = `assets/{noteId}/{filename}` 的文件名列表，统一走现有资产管线。
  - **关联是占位类型**（用户 260919：「先落一个能选但是不联动」）：能建列、能改名、能删除；单元格**暂不可填值**，只显示占位；数据结构预留 `{ tableId, recordIds[] }`，等做多表关联时再启用。
  - **明确不做「文本扩展类」字段**（用户 260919：勾选框 / 链接 / 电话 / 邮箱 / 评分 / 进度 都不要）——这些用文本或单选表达即可。
- 字段属性：**必填、默认值**（表单录入需要）。
- 视图配置：**筛选、排序、行高（常规 / 中等 / 高 / 超高 / 自定义 px）、隐藏列、列顺序、列宽**（排序的升降序选项随字段类型变化，见 §1.9）。
- 记录详情：字段纵向表单 + 上一条 / 下一条。

**v1 明确不做**（写下来防止被顺手做进去）

- 记录正文（每条记录一篇 Lake 富文本）——用户 260919 否决：「一条一个 Lake 太奢侈了」。
- 统计 / 汇总（逐列统计、组内汇总）——用户 260919 决定不做。
- 分组（多级分组、折叠全部）——v1.5，与看板一起考虑。
- 看板 / 画册 / 日历 / 甘特 / 透视表 / 地图 / 查询页面 / 排版打印；`views[]` 保留结构位，UI 只暴露「表格 + 表单」两种。
- 分享收集（表单的对外链接 / 权限 / 填写规则 / 催填）、公开分享、协同、权限。
- AI 相关全部（AI 字段、AI 筛选、AI 填色、AI 表格）。
- 导入导出（Excel 导入、导出应用）、自动化、按钮 / 流程字段。
- 人员 / 部门 / 群组 / 创建人 / 创建时间 / 修改人 / 修改时间（无协作模型，做出来是假字段）。
- 公式 / 查找引用 / 汇总字段（关联只做占位，见上；这些等后期做「多数据表关联」时再议）。
- 富文本 / 地理位置 / 条码 / 身份证号 / 手写签名 / 货币 / 勾选框 / 链接 / 电话 / 邮箱 / 评分 / 进度 字段。

## 4. 数据模型（产品口径）

> 结构继承 `SHEET-BITABLE-DESIGN-260918.md` §3.2，本节只补「云端实测后确定下来的语义」。

> **260919 修订**：一份正文不再等于一张表 —— 按用户要求改成一**文档多数据表**（形态对齐钉钉，见 §1.9）。
> 正文落在 `bitables/{id}.bitable.json`，与表格正文（`sheets/{id}.sheet.json`）平级；S3 仍走既有的内容寻址对象 + 清单，零新增前缀。

```ts
type BitableDoc = {                 // 一份正文 = 一个「数据表文档」
  kind: "bitable"; version: 1;
  tables: BitableTable[];           // 左侧数据表列表的顺序 = tables 顺序
  activeTableId: string;            // 上次打开的那张表
};

type BitableTable = {
  id: string; name: string;
  fields: BitableField[];           // 顺序 = 列顺序；fields[0] = 主字段（记录标题）
  records: BitableRecord[];         // 顺序 = 表格视图默认行序
  views: BitableView[];             // 视图 = 配置投影，不含数据
  activeViewId: string;
};

type BitableField = {
  id: string; name: string; type: FieldType;
  options?: { id: string; name: string; color?: string }[];  // 单选 / 多选
  required?: boolean; defaultValue?: unknown;                // v1：必填 + 默认值
  relation?: { tableId?: string; multiple?: boolean };        // 关联占位：目标表（v1 不联动）
  width?: number;                                            // 表格视图默认列宽（视图可覆盖）
};

type FieldType =                    // v1 实现的 7 种（其余类型留给以后，读到未知类型只读展示）
  | "text" | "number" | "select" | "multiSelect" | "date"
  | "attachment"                    // 「图片和附件」合一（260919 决定）
  | "relation";                     // 关联：v1 只占位，不联动（260919 决定）

type BitableRecord = {
  id: string;
  values: Record<string /* fieldId */, unknown>;             // 按 fieldId 存，不按列序
  createdAt: string; updatedAt: string;
};

type BitableView = {
  id: string; name: string; type: "grid" | "form";           // v1 只有这两种
  filters?: FilterRule[]; sorts?: SortRule[];
  rowHeight?: "low" | "medium" | "high" | "xhigh" | number;  // 数字 = 自定义像素
  fieldOrder?: string[]; hiddenFieldIds?: string[];
  // form 视图专有：哪些字段进表单、字段描述、是否必填（覆盖字段默认）
  formFieldIds?: string[]; formDescriptions?: Record<string, string>;
};
```

语义约定（`[实测]` 对齐云端）：

1. **三层归属**：**文档 ⊃ 数据表 ⊃（字段 / 记录 / 视图）**。字段与记录属于「表」，视图是「表」上的一层配置投影 —— 删视图不动任何数据（语雀实测确认）；删表则连带其字段/记录/视图。
2. **一个文档多张表**：`tables[]` 是左侧列表的真值来源（顺序即列表顺序）；新建/重命名/删除/排序都改这一层。v1 不做表的文件夹分组。
3. **视图不存数据**：筛选/排序/行高/列顺序/列宽/隐藏/（表单的选题与描述）全部是「视图配置」。
4. **主字段 = `fields[0]`**：语雀记录详情标题「未命名记录」即主字段未填的兜底文案；我们同样用它做记录标题与列表展示名。
5. **值按 `fieldId` 存**：加字段、改字段顺序、改字段名都不动已有记录（语雀行为一致）。
6. **图片与附件是同一个类型**：值 = 文件名数组，直接指向现有 `assets/{noteId}/{filename}`，复用资产管线与 `manifest.assets` 声明 —— 这是复用既有同步管线最大的红利，也是「图片就是附件」的落地方式。
7. **关联字段 v1 是占位**：`FieldType = "relation"` 可被建出来，字段定义里可以记 `relation.tableId`；**单元格不提供选值 UI**，`values[fieldId]` 预留 `{ tableId, recordIds: string[] }` 形状但 v1 不写入。⇒ 将来做多表关联时，**只加交互与取值，不动正文格式**。
8. **未知字段类型只读展示、不清空**：为以后加类型（公式/汇总等）留门。
9. **筛选/排序规则落在视图上**，不是打开面板时的临时 state —— 语雀「点开筛选就产生一条空规则并打角标」正是这条的证据。

## 7. 验收清单（产品视角，可直接照着点）

1. 目录树右键「新建数据表」→ 出现条目、可重命名/移动/删除/进回收站/恢复，与 Lake 文档无异。
2. 打开即表格视图，默认一张表（3 个字段：文本（主字段）/ 单选（待开始·进行中·已完成）/ 日期）+ 空记录；**打开的是数据表，不是 Lake 编辑器**。
3. 字段菜单里**只有 7 种类型**（文本 / 数字 / 单选 / 多选 / 日期 / 图片和附件 / 关联），**没有**勾选框、链接、电话、邮箱、评分、进度；
   增删改字段、拖拽改列序、隐藏/显示列、改列宽；重开文档后全部保持。
4. 增删记录、拖拽改行序、单元格按类型编辑，自动保存（无手动保存按钮，标题栏显示已保存）。
5. 视图级：筛选一条规则 + 一条排序 → 关掉面板再打开**规则仍在**；切换视图互不影响。
5b. 行高切到「高」「超高」「自定义 px」后表格立即变化，重开文档仍保持。
6. **多数据表**：左栏新建第 2 张表 → 两表字段互不影响；重命名 / 删除 / 拖拽排序生效；重开文档回到上次的表与视图。
7. **表单视图**：「填写表单」提交后，表格视图多出一条对应记录；必填校验生效；表单里没选的字段不出现在表单中。
8. **图片和附件字段**：插入图片/附件 → 文件落 `assets/{noteId}/`、`manifest.assets` 有声明、另一端能加载；清空该单元格后资产仍受「当前正文 ∪ 历史 refs ∪ 草稿 refs」保护。
8b. **关联占位字段**：能新建出「关联」列、能改名/删除；该列**单元格不可填值**（只显示占位），且不会影响同步与其它列。
9. 同步：A 建 → 同步 → B 拉取，另一端打开的是数据表；正文对象与 `manifest` 中 `kind = "bitable"` 正确；**往返 sha256 不变**。
