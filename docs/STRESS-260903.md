# S3 同步压测报告 STRESS-260903

> 目的：量化验证 `perf/s3-sync-asset-dedup` 分支的同步优化（资产清单差集上传、正文并发、
> manifest 链 O(3)+滞后裁剪、自检补强），并给出 master(改前)/分支(改后) A/B。
> 隔离：真实云跑在一次性前缀 `lake-stress-<ts>/`，afterAll + 复核 `listAll` 确认 0 残留；绝不碰 dev/正式数据。

## 怎么跑
- Tier A（离线、确定性、零网络、可进 CI）：`LAKE_RUN_BENCHMARK=1 npx vitest run src/core/syncEngine.benchmark.test.ts`
- Tier B（真实云墙钟，需凭证）：
  ```
  LAKE_RUN_BENCHMARK=1 \
  LAKE_STRESS_S3_ENDPOINT=... LAKE_STRESS_S3_REGION=... LAKE_STRESS_S3_BUCKET=... \
  LAKE_STRESS_S3_AK=... LAKE_STRESS_S3_SK=... \
  npx vitest run electron/syncStress.benchmark.test.ts
  ```
- A/B：`git worktree add /tmp/lake-master master`，把同名压测文件复制进去各跑一次对比。
- 凭证只从环境变量注入，不写入仓库。

## Tier B｜真实云（七牛 Kodo）墙钟
| 场景 | master(改前) | branch(改后) | 提升 |
|---|---|---|---|
| B1 首传 120 篇 / 240 资产 | 18406ms，**240 HEAD**，get=1 | **9566ms，0 HEAD**，get=1 | 时间 −48%（省掉 240 探测） |
| B1 churn 复同步 60 篇改名 | 5618ms，**120 HEAD** | **1046ms，0 HEAD**，资产 0 重传 | **−81%** |
| B2 12 次发布的 manifest 处理 | 52 次 manifest GET，驻留 10 份 | **15 次 GET，驻留 8 份** | 链回捞 −71%、驻留 ↓ |

（改后 B2 每次发布仅读 latest + 偶发滞后裁剪链，不再每发布回捞 8 份历史 manifest。）

## 结论
- 资产差集把「每对象一次 HEAD/GET 探测」降为 O(1)+O(缺失)：稳态/churn 场景资产零重传零探测，真实 churn 同步 5.6s→1.0s。
- 正文并发上传 + manifest 链 O(3)+滞后裁剪：多发布场景 manifest 回捞从 ~4.3/次降到 ~1.25/次，驻留从 10 降到 ≤8。
- 无未处理拒绝、失败即中止不发布；数据语义与红线不变（清单仍全量声明、GC 保留窗口/年龄保护不动）。

## 由此确立的新不变量（务必知后来人）
1. **`远端清单已声明该资产` ⇒ 云端该对象存在**（依据：发布顺序=先对象后清单；GC 只删「未被任何在留清单引用」的键 + 年龄保护）。因此同步用「清单声明差集」判存在，**不得**再退回逐对象 HEAD，也**不得**用「本机记过=已上传」的持久缓存（后者会因 GC 删除而失真，破坏跨端自愈）。
2. **兜底"未分类"笔记本仅在笔记真正回落到兜底父时惰性创建**（`resolveDefaultNotebook`/`effectiveParent()`），空库同步即使无内容安家也不得凭空生成。
