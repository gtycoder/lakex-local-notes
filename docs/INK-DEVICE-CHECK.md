# 手写板真机验收清单（Android 平板 + 手写笔）

> 目的：模拟器只能验证 Pointer Events 与数据链路，**延迟/压感/掌托只能在真机上看**。
> 照着做 1 遍约 15 分钟，把「实测」一列填掉，我们据此决定要不要改代码。
> 现在需要设备侧的结论都集中在这里，不靠猜。

## 0. 前置

1. 装包：`npm run android:build` 后 `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`（版本号只增不减，勿手改 gradle）。
2. 打开 App → 新建一篇手写板（编辑态）→ 手指或笔点一下进入编辑。
3. 桌面上另开一个终端连 CDP（页面 console 里直接调也行）：
   ```bash
   adb forward tcp:9335 tcp:9335
   node scripts/cdp-eval.mjs 9335 "1+1"
   ```

## 1. 延迟（落笔到出墨）

**操作**：连续写 20 个字（正常速度），再快速画一道 20 cm 长线。

**取数**：页面 console 执行
```js
__lakeInkInputStats()   // 笔迹输入统计（落笔/移动/中断计数）
__inkPerfStats()        // 保存/打开耗时与字节
```

| 观察 | 期望 | 实测 |
|---|---|---|
| 正常写字是否跟手（无明显拖影/滞后） | 主观「跟手」 | |
| 快速长线是否断成多段（丢点） | 不丢 | |
| 快速划线后再点空白处，是否残留「幽灵笔」 | 无 | |

## 2. 压感

**操作**：用笔从最轻到最重画 5 条横线；再画一笔快速轻扫。

| 观察 | 期望 | 实测 |
|---|---|---|
| 轻压是否**有**墨（不是完全不出） | 有细线 | |
| 重压是否明显变粗 | 有梯度 | |
| 同一条线内粗细变化是否自然（不突变） | 自然 | |
| 高亮笔是否等宽（不应随手速收锋） | 等宽 | |

> 若「轻压没墨」或「重压糊死」⇒ 要改 `pointFromClient` 的压力映射（`features/ink/InkPad.tsx`）；
> 若「粗细变化太猛/太钝」⇒ 改 `features/ink/inkStrokeStyle.ts` 的 `thinning`。

## 3. 掌托 / 多指（重点）

**操作**：A) 手掌自然压在屏幕上写字；B) 用两指同时快速划动；C) 先放笔尖再落掌；D) 先落掌再落笔。

| 场景 | 期望 | 实测 |
|---|---|---|
| A 掌托压屏写字 | 页面不滚动、不出杂线 | |
| B 两指划动 | 页面不被画花 | |
| C 笔在屏上时落掌 | 不打断当前笔画 | |
| D 掌托先压屏再落笔 | 笔能正常出墨 | |

> 现在**没有**「有笔时忽略 touch」的显式策略：日志里若看到 `pointerType:"touch"` 也在产生笔迹，
> 说明掌托会误画 ⇒ 需要加策略（判据：最近 N 秒内有 pen 活动就忽略 touch）。这是本轮预留的改动点。

## 4. 大文档（拿那本 335 页 PDF 导入手写板）

| 观察 | 期望 | 实测 |
|---|---|---|
| 打开文档到能写字 | < 1s | |
| 翻页（点下一页） | 无明显卡顿 | |
| 画 10 页批注后保存（看 `__inkPerfStats()` 的 save 样本） | < 50ms | |
| 全局预览（缩略图条）首开 | < 500ms | |
| 导入 300 页 PDF 时在前几页写字 | 可边导边写 | |

## 5. 结果怎么给我

把上面「实测」列填好（或直接截图 console 里的 `__lakeInkInputStats()` / `__inkPerfStats()` 输出）贴回来，
我据此做三件事之一：① 不改；② 改压力映射/掌托策略（`InkPad.tsx` + 护栏测试）；③ 改笔感参数（`inkStrokeStyle.ts`，改一个数就生效）。
**在没有真机数据之前，不会对这几处动刀**（本项目已因「凭直觉优化」踩过一次：预解码实测无收益）。
