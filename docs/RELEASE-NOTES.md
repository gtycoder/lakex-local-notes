# LakexLocalNotes v1.1.3

一次以**回收站删除语义（级联/恢复/彻底删除）**、**启动与退出稳定性**、**移动端删除一致性**为主的修正版。

## 回收站与删除

- **删除 = 整棵子树一起进回收站**：删除笔记本 / 分组 / 文档时，其下多级分组、子文档、孙文档全部一起移入回收站（不再只动被点的根）；恢复整棵回原位置，彻底删除整棵（正文/附件/历史/墓碑），同步索引对每篇被删文档写 `trashedAt`，其他设备会跟着移动。
- **批量/重复删除顺序无关且幂等**：批量里先删子项再删父项、或重复删除已在回收站的节点，都不会把子树拆成多个回收站根。
- **修复「删光笔记本后重启自动打开回收站文档」**：启动快照只收活跃文档（回收站 / 已彻底删除 / 父节点不在位 / 日记条目都不自动打开）；启动自愈清掉旧版本 bug 复活的幽灵欢迎笔记。
- **修复「打开回收站文档却关不掉、保存被拒、退不出」**：所有打开入口按 `trashedAt` 判「已删除」（只读 + 横幅 + 保存被拦明说）；退出闸只拦「还能保存」的脏标签，保存已失败/已删除的标签允许丢弃（仍尽力写本机草稿），⌘Q/关窗不再被永久拦住。
- **回收站行的「恢复 / 彻底删除」改为浮动按钮**：不再占用标题与时间宽度（hover / 选中 / 键盘聚焦时浮现）。

## 桌面端

- **启动不再硬开文档**：只恢复上次标签；没有可恢复标签时保持空态（不再用「上次打开 / 最近文档」兜底）。
- 文档被彻底删除 / 他端删除后，已打开标签自动收掉并提示可在回收站恢复。

## 移动端

- **删除笔记本 / 分组 / 文档与桌面完全对齐**：整棵子树一起进回收站；删除后**子树内已打开的标签全部关闭**（含首页删笔记本、目录树批量、文档列表批量、日记条目、缺正文清理等所有入口），不再留下「树里看不见、搜索里还在」的悬空子文档；恢复整棵、彻底删除整棵。
- **恢复位置修正**：子文档/子分组的原父是另一篇文档时，恢复后回到原父文档下（不再被移到笔记本根）。
- **批量删除先落盘**：批量/多选删除前先把在途编辑保存，再移入回收站，避免最后一段输入丢失。
- **打开中被删的文档不再卡住**：关闭 / 返回 / 完成编辑时会丢弃已删除标签并提示「可在回收站恢复」。

## 升级说明

- 桌面：覆盖安装新版本即可。
- Android：请安装新 APK（versionCode 自动递增，可覆盖安装）。
- 回收站语义不变：软删除可恢复；彻底删除不可恢复（含历史/附件）。
# LakexLocalNotes v1.1.2

一次以**多端同步数据安全**、**移动端首屏与同步性能**、**云同步开启闸门**为主的修正版。

## 同步（多端数据安全）

- **恢复后首次编辑不再被旧副本覆盖**（真实桶复现并修复）：删除→恢复→再编辑时，其他设备会正确拉取新内容，不再把旧正文传回覆盖。
- **附件失败不再静默**：上传失败/文件读不出时不再写「声明在、对象缺」的新声明；索引回退旧版本、给出可见告警，文件恢复可读后下一轮**自动补传**（无需再改文档）。
- **小记共享正文不再被误删**：两条内容相同的小记共用云端对象，删除/改写其一时不再毁掉另一条的正文。
- **「云端已删除（仅本地）」副本不再卡在活跃目录**：同一轮既发布又发现他端彻底删除时，副本正确进回收站、可恢复。
- **目录删除/恢复不再被其他设备的改名吞掉**：位置（目录/回收站状态）与内容分别合并。
- **小记「他端删除→本端恢复」跨端生效**，不再出现「已恢复又被删」的回弹。
- **拉取的小记时间戳不再变成 1970**（列表排序错乱）。
- 小记彻底删除会一并清掉附件声明前缀；首次上传按本地已删除裁剪；快路径拒绝把「云端已删除」副本重新上传（避免复活）。
- **冲突提示修正**：两端都改过时提示「已保留本地历史版本」，不再误报「远端内容不完整／下次重试」。
- **手动「立即清理」不再被 7 天保留窗口挡住**（预览与真删同参）。
- **彻底删除的云端对象改为「发布成功后再删」**（发布失败/重试时不提前删，索引保持一致）。
- **兜底「未分类」笔记本改为固定 id**（跨端同一本；用户自建的同名笔记本一律不动）。
- **云同步开启闸门**：没配置 S3 或没通过连接测试时**不能开启**云同步（开关只给「先测试通过才能开启」的红字提示），两端同口径。
- **编辑锁语义明确**：锁只锁本地编辑、不阻断同步；锁随同步传播，另一端收到后同样只读（真实桶 UI 路径已验证）。

## 移动端

- **首屏瘦身**：入口 JS 61,006 → **48,759B gz**（首屏资源图 353,397 → 341,652B）；「点击才出现」的预览浮层与标签/知识库页改为按需加载，冷启动更快。
- **同步记账性能**：本地同步基线从数据库整行搬到 gzip 文件（每次同步不再整行过桥）；小记重复点「保存并同步」不再重写基线。
- **云清理可预览**：设置→资源管理→云端未引用文件，先「预览」（将删数量/体积/保留 7 天）再确认清理；「候选数」与「已删数」分开。
- **移动 AI**：支持「服务供应商」配置（与桌面同目录/同字段），并可获取模型列表。
- **设置项对齐桌面**：顺序、长说明行上下布局、默认笔记本选择器、Secret 掩码逻辑修正。
- **日记条目新增「转为小记」**：正文与图片/附件搬进小记（原稿进回收站、可恢复；搬不了的块明说）。

## 桌面与界面

- **快捷键**：壳层快捷键接入思源口径（⌘P 搜索 / ⌘N 新建 / ⌘W 关闭标签 / ⇧⌘[ ⇧⌘] 切标签 / F9 立即同步）；第二批补 ⌃⇥ 切标签、⇧⌘G 锁定文档、⌥H 当前文档历史。
- **回收站窄分栏**：放不下时让出倒计时徽标，标题与「云端已删除」等告警保留（按行宽 340px + 是否另有徽标判断）。
- **日记本开放改名与换图标**（261113 裁决；仍不可删除/排序/作移动目标/取消日记标记）。
- **无障碍基线明文化**：对比度、reduced-motion、焦点可见、触控命中、键盘可达 5 条做得到的基线 + 已知未覆盖项（不声明 WCAG 等级）。
- 复核保留项收口：子树恢复语义钉死（F-10）、同步警告去重（F-11）、剪贴板尺寸边界登记（F-14）、清理用例超时（F-17）。

## 升级说明

- Android：`versionName 1.1.2` / `versionCode 11102`（从根 package.json 派生）；同一 release keystore 可覆盖升级、保留数据。
- **云同步开启闸门是行为变更**：升级后若开关打不开，请先在设置里「测试连接」，通过后再开启。
- **兜底「未分类」**：新建兜底笔记本使用固定 id（跨端同一本）；你自建的「未分类」笔记本保持原样，不会被改名或移动。
- 已知限制：其他设备对日记本的标题/图标改动在同步镜像里仍可能被应用（应用内不提供入口）；内核正文、Univer 表格、Drawnix 画板不在无障碍基线范围内。

## 验证

- 真实七牛桶多轮端到端复验（笔记本/目录/小记/资产/删除恢复/冲突/锁/云清理）与设备级验收；矩阵与数字见 `docs/HANDOFF.md` §1/§2。

# LakexLocalNotes v1.1.1

一次以**多端同步语义**与**日记本行为**为主的修正版；另有若干体验修复与移动端性能优化。

## 同步（多端）

- **回收站 = 特殊笔记本，删除 = 移动**：位置（所在目录/回收站状态）与正文分别合并——移动不会把两边各自的正文改动互相覆盖。
- 本地已在回收站的文档**仍能收到其他设备改的正文**，但保持回收站状态、**不会偷偷恢复**到目录里。
- **编辑锁独立合并**：其他设备持续编辑正文时，加锁/解锁也能正常同步；锁只保护本机只读（并随之传播），不阻断正文同步。
- 云端索引不再携带本机回收站容器 id（避免其他设备把「回收站」当成普通目录）。
- 其他设备把文档移入回收站时，本机**尚未同步的编辑会强制留一份历史快照**，不静默丢弃。
- **彻底删除目录后**云端索引不再残留该目录（其他设备不会把它重建出来）。
- 被其他设备删除的文档不再**永久卡在活跃目录树**里。
- 单篇同步失败（坏文件/读不到等）只降级为该条**警告**，不再让整轮同步失败。

## 回收站

- **「云端已删除（仅本地）」副本可正常只读预览与恢复**：整行可点、标题不再被徽标挤没；正文缺失时会给出明确提示。

## 日记本

- **日记本固定不可变**：移除「取消日记标记（整本）」。日记本不可删除、改名、换图标、排序，也不作为移动目标；「普通笔记本 → 日记本」只允许单向升级。
- **单篇条目有两个出口**：
  - **转为文档**：把这篇日记移动到知识库的其他笔记本，成为普通文档；共享弹窗只选笔记本、标题可改；正文、历史、回收站、云端索引跟着走。
  - **转为小记**：用该日记的原正文生成一条小记，图片/附件一起搬到小记资产（原资产保留），原稿进入回收站、可恢复；搬不了的块会**逐项提示**，不静默丢内容。

## 体验与修复

- **操作提示全空间可见**：所有一级空间（知识库/小记/日记/AI 写作/标签）都能看到成功/提醒提示（此前只有知识库空间可以看到）。
- **复制含图片内容写入原图尺寸**：不再把界面显示尺寸写回正文（粘贴到别处时尺寸正确）。
- **同步警告可逐项查看**：桌面与移动用同一套文案，不再只给一句笼统提示。
- **移动端编辑锁真正生效**：锁定文档为只读 + 顶部横幅 + 保存被拦并说明；陈旧的小记保存不再把已删内容静默复活；其他设备彻底删除后本机保留「云端已删除（仅本地）」副本。

## 性能

- 移动端小记「保存并同步」快路径：首次 push-state 耗时 p50 由 **444ms 降至 150ms**（同设备、同数据实测）。

## 升级说明

- Android：`versionName 1.1.1` / `versionCode 11101`（按「1000 + major×10000 + minor×100 + patch」从根 package.json 派生）；同一 release keystore 可直接覆盖升级、保留数据。
- **日记本不可取消是行为变更**：旧入口已移除；已有普通笔记本不会自动变成日记本。
- **移动端暂不提供「转为小记」入口**（桌面端可用；「转为文档」两端都有）。
- 已知限制：其他设备对日记本的标题/图标改动在同步镜像里仍可能被应用（应用内不提供入口、界面不暴露；不做字段冻结）。

## 验证

- `tsc` 0 错；完整 vitest、ui-metrics、check:core、check:mobileui、diff-check 全部通过（**具体数字见 docs/HANDOFF.md §1，本文件不抄计数**）。
- 设备级门禁（移动快照矩阵、23 屏走查、桌面 42 态等）以 docs/HANDOFF.md §1/§3 为准。

# LakexLocalNotes v1.1.0

两个新空间：**AI 写作**（桌面）与**日记**（桌面 + Android）。

## AI 写作（桌面，⌘3）

- 新增独立空间：左栏「新对话 + 历史记录（按今天/昨天/更早分组，可重命名与删除）」，主区分「对话写作 / 多文档推理」。
- 提示词库 6 张卡（点卡 = 挂成输入卡上的 chip，不写正文）；多文档可「按时间快捷组」或「按笔记本勾选」，chip 显示「N 篇文档」。
- 深度思考默认开启且不提供关闭入口；思考内容与正文分开显示，都不进上下文。
- 答案用 Lake 内核只读视图渲染：任务清单、表格、引用、代码、行内与块级公式都按内核原生解析；生成中先走轻量 Markdown，收尾无缝切成富文本。
- 「生成文档」只选到笔记本（不选目录），「保存到小记」落成小记卡片。
- 会话与消息只存本机，**不进同步、不进搜索、不进目录树**；模型使用你已有的 AI 供应商配置，未配置时页面给引导。

## 日记（桌面 ⌘4 · Android 首页第 4 个 tab）

- 新增独立空间，**数据仍是普通文档**：一本"日记"笔记本 + 标题就是日期 +「年 → 月」分组自动收纳。历史快照、回收站、全文搜索、导出、云同步全部沿用文档那一套，不新建数据结构。
- 写今天 / 翻历史 / 日记内搜索（复用全库搜索并按日记范围收窄，不新增索引）。
- **转为文档**：右键（Android 在条目操作入口）把某一天的日记移到任意笔记本，成为正式文档；正文与历史跟着走，不复制。
- 日记不打标签；v1 不做缺天提醒、补写任意日期、月历视图。

## 同步与数据

- lake 索引新增 `folders[].space`（日记本标记）：发布时显式写（非日记写 null），未知值按非日记处理，坏端写的 group+space 会被就地归一。
- 移动端 SQLite schema 11 → 12（新增 `folders.space`），版本门按既有方式 +1。
- 便携包与整库备份保留日记标记（快照天然带列）。

## 修复

- 修复移动端便携包导入丢失日记标记：导入后日记本曾降级成普通笔记本、再点「写今天」会建出第二本。
- 修复移动端日记页数据源缺 notes 行（页内曾恒为空、日记内搜索恒 0 命中）。
- 移动端「多个日记本」按契约取第一个并告警，不再静默。

## 验证

- `tsc` 0 错；vitest **818 文件（807 通过 / 11 跳过）· 5148 用例通过 / 12 跳过 / 0 失败**；ui-metrics、check:core、check:mobileui、diff-check 通过。
- 桌面与移动两条 `vite build` 通过。设备级门禁（移动 6 态 + 23 屏走查、桌面 42 态）未随本版重跑，见 `docs/HANDOFF.md` §3。

## 升级说明

- Android：自 v1.0.2 起同一 release keystore 可直接覆盖升级（保留数据）；本版 `versionName 1.1.0` / `versionCode 11100`。
- 日记与 AI 写作都是**新增**能力，不改动既有数据形态：升级后原有文档/小记/标签/同步状态不受影响；移动端首次启动会做一次 schema +1。
