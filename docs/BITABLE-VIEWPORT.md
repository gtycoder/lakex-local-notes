# 多维表行窗口契约

适用：桌面自研多维表的 Grid 和关联记录选择器。它不是 Lake 富文本内核或 Univer 表格的配置。
当前实测与剩余发布验收以 `HANDOFF.md` 为准。

## 数据与渲染边界

- 正文继续用 `BitableDoc v1`；core、编辑会话、历史、附件/S3协议不变，不做迁移。
- 记录全集保留在模型中。筛选、排序、分组、查重、统计、搜索、复制/粘贴按完整投影求值，不能只处理挂载行。
- `BitableVirtualBody` 是主Grid/关联选择器唯一行窗口实现，依赖 `@tanstack/react-virtual@3.14.19`（传递依赖virtual-core在lock中为3.19.4）；不保留另一套全量Grid或运行时开关。
- 窗口为可见行 + 上下各6条缓冲 + 最多1条编辑/组合输入行。隐藏标签卸载数据行，保留数据和设备本地导航。
- `BitableViewportCell` 用默认 `React.memo`；值、字段、选区、填色、回调、必要关联/时间上下文都参与更新，不忽略函数prop。

## 几何与生命周期

| 条目 | 高度来源 |
|---|---|
| 主表记录 | 视图低/中/高/超高：36/44/64/96px |
| 显式数字行高 | 视图值 + 实际测量，不能只用估计 |
| 主表分组头/组内添加/间隔 | 36/32/20px |
| 主表末尾添加行 | 34px（已有按钮/内距/边框） |
| 关联选择器记录/分组头 | 36/32px |

- `projectViewportGeometry` 只保留 key/size/source，不保留记录值、React元素。行ID顺序和高度未变时复用元数据；重排、换ID、增删、行高或分组条目变化使其失效。
- 行React缓存仅保存当前挂载窗口；值、回调、前后添加条目变化仍必须刷新，滚过的行当场移出缓存。
- 主表列宽由完整字段模型确定；空投影末列33px，有数据时40px。关联选择器字段宽度取80–320px，不能让屏外内容决定列宽。
- 屏外键盘跳格先按ID定位投影索引，再滚动并等待真实DOM；异步返回前复核表/视图身份。
- 拖行按视口坐标命中、边缘自动滚动；取消/隐藏/换表/卸载时释放document监听和动画帧，取消不能意外提交。
- 组合输入可临时保留正在编辑的一行，IME Enter不能被网格导航抢走。

## 只读与资源

- 锁定/回收站/历史等入口的只读和保存守卫保持原语义。
- 关联选择器通过同一个 `CellEditor` 的 `readOnlyScalarDisplay` 展示文本/数字，减少只读input的value tracker；默认锁定主表仍保留原生选字复制入口。可编辑格不会因该标志变成只读展示。
- 附件仍走原上传/删除/改名/预览组件，图片用既有缩略图服务；不把附件字节或base64塞进视口缓存。
- 不增加自动GC、V8堆上限、永久全格缓存，不关闭GPU/sandbox/contextIsolation换性能。

## 验证与接入标准

用户确认：目标5000×20的主要加载/交互不进入秒级即可接受。33ms滚动、50ms输入等精细目标保留为优化参考，不再是阻止接入的硬门槛。

接入必须通过：类型/全库测试/桌面与移动构建、样式与core边界、真实包全模型/末行/组合输入/跨屏复制粘贴/撤销重做/关联/只读/切标签回归，以及窗口有界与关闭回收检查。
内存同时看正常运行采样峰、稳定保留、关闭回收；强制GC仅可作为单列诊断，不代替正常测量。

低内存设备、长时间使用、真实大图、高扇出关联、完整发布功能矩阵仍需发版前验证；接入不等于签名、公证、分发或所有设备验收完成。

可复跑真包检查：`npm run test:bitable:packaged`，环境与合成夹具流程见 `scripts/packaged-performance/README.md`。
新依赖许可随 `public/third-party/tanstack-virtual.LICENSE.txt` 进入发布资源；升级时必须同步核对。
