### 二、设计特异性判定（先说结论）

**当前视觉世界是「品类可互换」的，不是为本产品做的。**

证据：近白平面（`--lake-bg-panel #ffffff` 压在 `--lake-bg-window #f4f5f7` 上）+ 发丝线分隔（`--lake-border-1 #e8eaee` / `#f0f2f5`）+ 去饱和板岩蓝强调色（`--lake-accent #5b6f96`，仅以 `--lake-accent-tint #eceff5` 极淡形式出现）+ 统一 1.75px lucide 线性图标 + 6/8/10/14/20 规整圆角。这套组合可以是任何 Electron CRUD 工具，看不出「语雀 Lake 内核 / 本地优先 / 自持数据」。

最讽刺的一点：产品唯一真正独家的颜色是**内核绿 `--lake-kernel-brand-green #00b96b`**（`tokens.css` 明确写它是「Lake 的标志、也是『正文由 lakex 渲染』的可见证据」），却只出现在工具条最左那个「+」图标上——**最强签名被藏进最不起眼的角落**。

**机械扫描（Assessment B）**：`impeccable detect --json src` exit 2，共 **16 处**、全为 warning：`side-tab` ×9、`broken-image` ×3、`layout-transition` ×4。
经 B 逐条核对源码后的**误报**：3 个 `broken-image` 全是测试字符串/正则（`lakeDocForm.test.ts:30`、`imagePreview.test.ts:51`、`imagePreview.ts:101` 的 `/<img\b[^>]*>/gi`）；`bitableFillRules.css:22` 与 `mobile.css:771` 是**有意的**行侧填色条（`data-fill-side`）；`markdown.css:54` / `quick-notes.css:235` 是标准引用块左竖线；`chrome.css:620` 是进度条宽度动画——均属边界误报。
**真命中**：① 产品 toast/snackbar 的**粗左色边** 5 处（`chrome.css:564`、`kit.css:216`、`compat.css:179`、`dialogs.css:70`、`mobile-kit.css:13`）——这正是「AI 生成界面」最典型的痕迹簇；② **动画布局属性** 3 处（`shell.css:672` 目录筛选行 height 0↔29px、`chrome.css:286` 边缘热区 width/top、`kit.css:301` 开关 knob width）。

**页面内叠加层（overlay）**：**无**。注入被渲染进程 CSP 拦截（`script-src 'self' 'sha256-…'`、无 `unsafe-inline`、无 `wasm-unsafe-eval`），detector 的 WASM 规则引擎在该渲染器里**无法运行**。回退信号 = **只有 CLI 检测**；本轮**不宣称任何用户可见覆盖层**。

### 三、总体印象

峰值是**编辑器本身**——Lake 内核的所见即所得是真正的资产。谷值是把编辑器包起来的 chrome：四层近白灰带、去饱和冷灰蓝、发丝线，整体读作「内部工具 / 未完成」。最大的机会不是换配色，而是**让文档重新成为屏幕上最亮、最安静的那件事**。

### 四、做得好的

1. **设计系统骨架是真资产**：`@layer legacy,tokens,kit,shell,feature,overlay,a11y` 显式层序、令牌单一来源 = `themes/*`（浅/深/暖只换变量、几何不动）、`kit.css` 的 `ln-*` 原语、`Overlay.tsx` 浮层原语、`a11y.css` 最高层、`zOrder.test.ts` 强制层序。重设计应把它当**主干**。
2. **文档状态栏语义分层专业**：`synced`（绿）/`pending`（琥珀）/`error`（红）/`sync`（青）/`local-only`（中性）各配软底色——对本地优先工具这是对的机制。
3. **设置项文案罕见地好**：每个开关写明「开启=…；关闭（默认）=…」，还解释两个工具栏互相独立可任意组合。值得保留并发扬。

### 五、优先问题

**[P0] 视觉层级缺失——万物同一近白值，读作灰阶半成品**
- 为何重要：用户无法在 200ms 内区分「内容 vs 工具」；第一印象抵消了产品「自持、精致」的定位。
- 修复：建立**三阶表面价值**（画布 < 面板 < 工具轨），先删掉至少一层发丝线；用已有的 `--lake-shadow-card/popover/dialog` 给目录树 peek、菜单、状态栏真实纵深；让**活动 tab** 成为全屏最强元素。
- 建议命令：`$impeccable layout`（或 `$impeccable bolder`）

**[P1] 顶部四条等重 chrome 带吃掉约 106px**
- 证据：`--topbar-height 38px` + 4px 拼接缝 + `--breadcrumb-height 30px` + `--editor-toolbar-height 34px`；752px 高窗口下正文有效高度被压掉约一成四，且四条带字重/底色几乎相同。
- 为何重要：笔记软件的高频动作是「看正文」，chrome 越重正文越退。
- 修复：用**表面值/字重**而非分隔线区分四条带；面包屑降权（更浅更小）或折进工具条；确保正文顶部比现在高 ≥40px。
- 建议命令：`$impeccable distill` + `$impeccable layout`

**[P1] 强调色形同虚设（#5b6f96 几乎只以极淡 tint 出现）**
- 为何重要：全屏没有视觉锚点、没有品牌，正是「AI 生成后台」观感的来源。
- 修复：定义一组**有存在感的 accent 角色**——至少一处高饱和、高置信的使用（主操作/活动导航/焦点），并在 tab/导航/开关间保持一致；或干脆拥抱 Lake 内核绿 `#00b96b` 作唯一品牌重音。
- 建议命令：`$impeccable colorize` + `$impeccable bolder`

**[P2] 编辑区阅读行宽无上限**
- 证据：`app/editor.css` 只给 `.ne-engine` 左右各 `padding:56px`，**没有 max-width**；02-doc 实测正文列约 1167px，16px 下≈70 全角字/行，远超舒适行宽。
- 修复：给阅读列设上限（约 660–720px）并居中；大纲 rail 独立占位。
- 建议命令：`$impeccable typeset` + `$impeccable layout`

**[P2] 图标语言混用、光学尺寸不一**
- 证据：`base.css` 定 `svg.lucide{stroke-width:1.75}`，但界面同时有 emoji 感的锁/⋮、lucide 线性图标、内核雪碧图（33 个 `use` 符号）；字号在 14/16/18/22 间跳。
- 修复：**一个图标族、一个光学尺寸、一个描边**；清除 emoji 字形。
- 建议命令：`$impeccable polish` + `$impeccable document`

**[P2] 「AI 生成」痕迹簇（机械可检出）**
- 证据：产品 toast/snackbar 粗左色边 5 处 + 动画布局属性 3 处（见「机械扫描」）。
- 修复：toast 改用「表面 + 1px 描边 + 图标色」表达状态，不用单侧 3px 色条；布局属性动画改 `transform`/`grid-template-rows`。
- 建议命令：`$impeccable polish` + `$impeccable animate`

**[P3] 内联样式与 `!important` 漂移**
- 证据：组件内联 `style={{…}}` 32 处（`AGENTS.md` 禁止）、源码 `!important` 70 处（门禁只覆盖面以 9 通过）、live CSSOM 355。
- 修复：把 JS 内联样式收敛进 `--lake-*` 令牌与 `kit.css`；核对门禁范围，把移动端/游离文件的 `!important` 计入口径。
- 建议命令：`$impeccable polish` + `$impeccable document`

### 八、值得深思的问题

- 你真正独家的颜色是 Lake 内核绿 `#00b96b`——如果整个界面围绕这一记自信的品牌重音来建，而不是用一层读起来像雾的板岩蓝，会怎样？
